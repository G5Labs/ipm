## Initial finding

### P1 — Bound failure-record admission after the publication deadline

At `backend/g5-api-core/src/services/workspace_pull_request_create.rs:518`, failure recording calls `caller.source_db(state, source).await` after the only `tokio::time::timeout` has finished. For a continuation this first awaits `scoped_db_for_user_actor_in_org` (same file, lines 165–167). That helper calls `PermissionService::require_user_scopes_on_conn` before returning (`backend/g5-api-core/src/db/scoped.rs:710–720`), which executes the SQL function `authz.lock_user_scope_authority` and waits for `FOR SHARE` on the actor's membership and scope-grant rows. The local five-second lock timeout is set only afterward (`workspace_pull_request_create.rs:187–193`). There is no default statement/lock deadline in pool setup, and this repair removes the worker's former outer 120-second deadline.

Concrete counterexample: an administrative transaction holds `FOR UPDATE` on the source owner's `org_memberships` row. Discovery captures the current PR/source/actor, publication admission reaches the scope lock and times out; the failure path retries that same admission without any deadline. The scan then waits indefinitely instead of visiting later eligible PRs, and the new persistent advisory scan owner prevents other replicas from taking over. Pool acquisition timeout does not bound a query once its connection is acquired.

Governing: `g5.architecture.recovery.progress`, `g5.governance.pr.follow-push`, and the follow-up plan's bounded error-recording requirement. Keep authorization intact while adding a bounded error-recording budget that includes acquisition and scope admission, or establish SQL timeout before those scope locks. On inability to record, retain durable retry inventory and allow later PRs to progress. Regression: hold a membership/grant authority lock through the short publication deadline and failure-recording window; assert a later eligible PR progresses before release, then release and verify the blocked PR eventually refreshes. The new test holds a PR row lock and releases it after 1.1 seconds, so it does not exercise this earlier unbounded authorization wait.

This is a source-proven regression in deadline coverage; no DB test was run by this reviewer.
