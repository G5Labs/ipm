## Raw findings saved before sharing

### R1 · P2 · A PR update during the first list request can be lost

- **Path:** `frontend/src/lib/ws.ts:991–996`, `workspace.pull_request_updated`; `frontend/src/hooks/useWorkspace.ts:513–536`, `workspacePullRequestsQueryOptions`.
- **Trigger:** the source or target PR list has its first request outstanding with a snapshot at A. Automatic refresh commits B and its WebSocket event arrives before that request resolves. `invalidateQueries` reuses the outstanding first request because the query has no data yet; its stale A response then clears invalidation. No second request is issued.
- **Consequence:** the PR dialog/list continues showing A or an obsolete pending/error state after automatic publication has completed. The query has no polling fallback, and subsequent worker scans need not emit another update once B is complete. It stays stale until focus/navigation/manual mutation or another event. Server-side exact-commit checks still protect merges; this is a visible freshness/recovery failure, not evidence of an unsafe merge.
- **Governing obligations:** `g5.governance.pr.follow-push`, `g5.architecture.pr_flow`, `g5.design.authority`; the design explicitly includes all three PR consumers and concurrent refresh.
- **Evidence:** an isolated Vitest probe imports the actual `WebSocketManager` and installed TanStack `QueryClient`/`QueryObserver`, mounts an active first query, invokes the actual `handleEvent` update handler, then releases the A response. The expected B assertion fails with A. A separate plain Query Core probe reports one query call and `isInvalidated: false` afterward. Existing `ws.workspaceAuthority.test.ts` seeds cached data before the event and only checks invalidation, so it does not discriminate this case.
- **Proposed repair/check:** use main's existing `invalidateAndReadAgain` helper for the PR query family, canceling outstanding first reads before invalidation. Add a real observer/cache regression that asserts B is rendered after this ordering, including source and target prefixes and preservation of unrelated workspaces.

### R2 · P2 · Reconnect does not recover missed automatic PR updates

- **Path:** `frontend/src/lib/ws.ts:1331–1383`, `invalidateAllSubscribedCaches`, workspace case; branch's new PR event handler at `991–996`.
- **Trigger:** a PR list is mounted at A, its workspace WebSocket disconnects, and the server completes automatic refresh or records failure while disconnected. The socket reconnects successfully.
- **Consequence:** workspace reconnect invalidates many query families and main's comment/review-thread families, but never `workspace-pull-requests`. With no polling in the PR list query and no new event after a completed refresh, the source/target UI can retain A or obsolete success/error evidence even after reconnect. This is a separate recovery boundary from R1: it fails with already-loaded cached data, without any first-read race.
- **Governing obligations:** `g5.governance.pr.follow-push` (visible recoverable refresh), `g5.design.commit-notify` (reconnect recovers committed facts rather than relying on the event as the sole authority), and `g5.architecture.pr_flow`.
- **Evidence:** a second isolated Vitest probe mounts an actual query observer at A, changes the query's authoritative test source to B, subscribes the manager's workspace channel and invokes its actual `invalidateAllSubscribedCaches` reconnect path. The expected B assertion fails with A. Source inspection confirms the only `workspace-pull-requests` reference in `ws.ts` is the new event handler; the reconnect path and `invalidateAuthoritativeCut` omit it.
- **Proposed repair/check:** refresh `['workspace-pull-requests', channelId]` in workspace reconnect using the same race-safe helper as R1. Add reconnect coverage with an already-mounted source and target PR query, and with a first read outstanding. No new ontology rule or second event mechanism is needed.

Both findings are retained branch-consumer defects, not evidence that the rebase dropped a previously working PR handler. Main's new race-safe comment invalidation helper makes the minimal shared repair available in this checkout.
