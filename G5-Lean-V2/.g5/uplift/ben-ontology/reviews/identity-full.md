## Remaining coverage and consistency limits

The model suite supplies meaningful positive, negative and failure paths, but its many direct guard/Boolean abstractions do not prove enforcement beneath those guards. In particular, guest descendant termination, durable journal failures across process restart, provider translation and cache files, PostgreSQL isolation/locking, native filesystem writers, approval evidence parsing, all notification audience branches, and browser event/header parsing require independent runtime tests. The canonical evidence must keep those limits beside the applicable claims. Preview single-use is within one live API process; there is no cross-restart proof.

The original invitation proof/expiry boundary had no independent broken proof/expiry control; the repair model adds proof sensitivity, while expiry passage remains a required runtime case. `QuestionVotes.RevisionAttributed` allows any revision up to the observed current value and therefore does not discriminate an incorrect older-but-valid revision: exact read-result attribution remains a source/runtime check. Module capability checks abstract the actual intersection; preview sanitizer checks abstract parsing. These are sensitivity gaps, not waived coverage obligations.

Keep source-level overlaps (chat adapter/translation, fork overview/detail, module input/frozen attempt) visible in the source comparison rather than deleting human meaning. Agent refinements should reference the existing source parent and add only decision boundaries. `QuestionDecision`/`QuestionOwnership` are overlapping concern models of the same contract, not two independent coverage credits; publication reuses the selected-file Save owner and retains that owner's known gaps. CI-G4 names the formerly CI-Q2 retired-settings discrepancy; its existence is supported, but its replacement product policy is still unspecified.
