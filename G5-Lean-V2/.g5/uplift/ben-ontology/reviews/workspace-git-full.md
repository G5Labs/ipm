## Execution and assurance

There are **112 workspace configurations and 87 Git configurations: 199 current receipts**, each with matching model/configuration fingerprints and a retained log. Every configuration was executed in this review; none relies solely on a saved previous execution. Safety success requires exit 0 plus TLC's success message. Negative, as-built divergence and reachability cases require exit 12 plus the exact named invariant. Parser/successor-completeness errors during new model construction were rejected, corrected and rerun; none counts as evidence. The workspace runner now records exact command and UTC start time. Both runners use the pinned 1.7.4 jar (`936a262…e88`). Outcomes: 39 safety passes, 11 scoped liveness passes, 46 reachability witnesses, 94 deliberate broken/comparison controls, eight as-built-divergence checks (including the repeated import comparison), and one stronger-policy assurance limit. See [workspace receipts](https://github.com/G5Labs/G5-Lean/blob/38046b2854bb8bbd6f061e20ee9596d5d61102d0/.g5/TLA_verification/ben-ontology/workspace/results.json) and [Git receipts](https://github.com/G5Labs/G5-Lean/blob/38046b2854bb8bbd6f061e20ee9596d5d61102d0/.g5/TLA_verification/ben-ontology/git/runs.json).

Models distinguish safety, deliberate broken controls, real as-built divergence and legitimate completion witnesses. Many finite terminal/refusal models disable deadlock checking; several others explicitly permit quiescence. Consequently no campaign-wide deadlock-freedom claim is made. Liveness is only the named fair, finite-change checks listed below. External network/SQL/VM semantics remain binding premises, not formal refinement proofs. New repair models preserve interleavings relevant to their comparison, but their proposed gates still need implementation and real system tests.
