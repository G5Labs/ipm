## Findings and corrections

1. **Preview as-built settlement omitted a relevant failure continuation.** `PreviewLifecycle` required dead application state before settlement even in its as-built variant. In code, [stop_app_group](../../../../backend/g5d/src/cli/preview_serve.rs#L434) logs termination failure and drops the final group-signal result; [run_preview](../../../../backend/g5d/src/cli/preview_serve.rs#L380) still runs cleanup and can report success, and [terminal task settlement](../../../../backend/g5-api-core/src/services/agents/task_lifecycle.rs#L3124) settles the preview intent. The corrected model allows owner-close/self-exit settlement after the failed stop attempt and cleanup. The new `NoOverlappingApps` trace reaches a second application while the first remains alive. The intended reap gate preserves both cleanup ordering and absence of overlap, with legitimate cleanup/restart witnesses. This strengthens **RUNTIME-004**, rather than introducing another defect. A failure return alone does not repair it if failed tasks still clear the admission barrier. Whole-VM shutdown/restart is outside this two-task model; its failure does not manufacture an in-place restart witness.
2. **Image choice assertions had no discriminating controls.** Existing controls challenged pin validity and compatibility but not `PinWins` or `DefaultOnlyIfAbsent`. Two new controls alter only selected image choice; each violates its own named assertion. Normal pin/default witnesses and the unchanged safe behavior pass. This is an evidence sensitivity correction, not a new code defect.
3. **Cloud compensation can use existing lifecycle ownership within the checked envelope.** The prior passing design added a hypothetical independent `deleteClaim`. New `CloudLinkage-reuse-row` leaves live unlinked results to the existing repair owner and compensates only results whose host record is already terminal; all linking writers must continue to refuse terminal rows. It passes the prior `NoRevive`, `NoOwnedCompensation`, callback and compensation completion obligations, plus `LiveHostPreserved` and conditional live-result reconciliation. The independent-claim-only design fails `LiveHostPreserved`: `Create → Hello → Reply → ObserveOwnership → Compensate` deletes a ready unlinked host without recovery attachment. Such a row can already accept placement, so excluding recovery alone is insufficient. Separate repair and compensation witnesses rule out universal refusal. Both original passing comparisons have 31 distinct states; those weaker checks did not establish preservation of a live unlinked host. Adding a terminal-lifecycle guard to the independent-claim design would make its new claim redundant for this modeled boundary. The reuse candidate avoids a new durable claim and wins **conditionally**, not globally. Multiple results, identity reuse, failed deletion and cross-replica recovery still require implementation checks.

## Coverage and ontology handoff

The runtime set covers important admission, authority, refusal, concurrency and recovery slices, but **does not establish high coverage of every runtime behavioral obligation**. Unexecuted areas include cache startup reconstruction and same-key replacement, mutation replay expiry/crash outcomes, full readiness and resource sizing, host control event dedup, VM physical singleton, autoscale, retry-budget/multiple-result cloud recovery, preview OS group death and end-to-end browser behavior. Direct source inspection keeps these visible; it does not turn them into structural nonbehavior or passing model coverage.

Canonical integration should preserve the original human commitments and remove repetition from agent additions: preview admission references `g5.vm.preview-exclusive` and `g5.data.identity.incarnation` while owning lock/request replay and listener-ready details; terminal attachment references the original offset-resume owner while owning stale generation/unsafe-write handling and unavailable-offset reset. The cloud block contains independently changeable accepted-insert, orphan-observation and compensation rules; split by meaning with stable lineage, not one block per predicate. Update RUNTIME-004's metadata to include unsafe settlement/restart and RUNTIME-007's design evidence to prefer the conditional reused-owner alternative. Neither change closes its application gap.
