## Findings for the shared code-gap ledger

### GIT-GAP-1 — automatic import can reveal part of an accepted multi-repository PR

**Classification:** source-bound implementation divergence from `g5.git.multi-repo-merge`; runtime reproduction still missing.

Ben requires a parent merge to be observed atomically across repositories and says external parents pull across all repos. The explicit provider-first import does propagate every member’s failure (`workspace_pull_request_provider_lifecycle.rs:227–403`). However, automatic import is an alternate writer. `import_hold` (`remote_integrations.rs:202–225`) stops holding when all provider rows are `merged`, before the G5 PR’s local import necessarily completes. Worker co-member preparation (`worker.rs:1492–1608`) skips claim, credential, fetch and incompatible-history failures. `1758–1825` creates the publication from the primary plus only retained co-members; it does not require all repos of that accepted PR.

Reachable model schedule: provider accepts both members; outcomes become durably merged while G5 PR remains open; all-member explicit import fails on the second repo; background pull sees both provider outcomes merged, so hold is false; first repo fetch succeeds and second fails; a valid atomic internal cut publishes first-new/second-old. `ProviderImport.current.log` violates `NoPartialWorkspaceMerge`. The model does not manufacture an unfenced writer; it uses the current candidate subset passed to the owner. It preserves the existing protection during partial provider acceptance and verifies that separately.

**Missing runtime case:** start one two-repository provider-first merge, accept both PRs, fail second repo import/fetch, then run automatic integration for the first with second-member fetch or lease failure. Observe fresh authorized reader snapshots and PR status: no first-new/second-old cut should become visible under the strict Ben contract. Restore second fetch and verify both land once. Check the persisted provider records, real queue leases, complete Git vector and real branch-commit consumers rather than a model-only unit test.

### GIT-GAP-2 — resolved by merged admission-time policy

**Disposition:** closed as a code-defect candidate during step 5 iteration 1; retained trace is an assurance limit. No new effect-time requirement or open question is proposed.

The original merged source at `32b2d174` was directly read: `.g5/chat_intent/ben-show-PR-status/external-pr-status-and-merge-gate.md` and `.g5/pr_ontology_diff_design/ben-show-PR-status/ontology-plan.md`. The human answers require checks/statuses first, any failing or pending/incomplete check to block when the admin setting is enabled, and default-off behavior. The accepted design explicitly calls the gate an **admission check before existing preflight/provider merge**, describes provider checks as **point-in-time observations**, and calls the knob **earlier/additive to provider branch protection**. Required-context integration was deferred. Commit `683e2d67` implemented the knob and verdict; `94b03678` aligned the source workspace reader. This evidence resolves the earlier conditional concern without weakening Ben’s observation contract or inventing a stronger human policy.

`ensure_external_checks_merge_policy` (`routes/workspaces.rs:4744–4819`) requests current checks and derives the verdict server-side. Provider merge checks the selected source/target and sends the expected source SHA (`workspace_pull_request_provider_lifecycle.rs:1894–2025`). A same-SHA rerun after the verdict can nevertheless be pending when the provider accepts, unless its own protection refuses. `ExternalChecks.current.log` demonstrates exactly this timing while preserving the accepted source SHA. `ExternalChecks.boundary` is a hypothetical stronger comparator; it is not the governing contract and another read alone cannot make it atomic.

An optional runtime assurance case can pause after stabilized check read, restart a same-SHA attempt, and accept the expected-SHA merge with provider check protection disabled. Repeat with source-head drift and with provider protection to distinguish G5 admission, SHA pinning and provider enforcement. No production provider write or runtime test was attempted.
