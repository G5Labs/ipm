## Evidence and inspected scope

The machine-readable [source manifest](https://github.com/G5Labs/G5-Lean/blob/38046b2854bb8bbd6f061e20ee9596d5d61102d0/.g5/TLA_verification/ben-ontology/runtime/source-manifest.json) pins the whole-file SHA256 and Git object for each directly inspected file and the ranges actually read. Partial reads are not whole-file coverage. The file/line inventory covers 33,902 lines in host services, runtime facade, host runtime, dispatcher, terminal and host/preview routes; it is a discovery denominator, not a read count. Related image, cloud, module and frontend owners add further source areas beyond that inventory. Search hits and file lists count only as discovery.

Directly traced boundaries:

- Placement takes the org advisory lock before quota, locks workspace then VM, counts `starting/running/stopping`, selects same-org/region ready qualified hosts with capacity and host-row lock, increments epoch and chooses a fresh VM ID. Drain writes `draining` under the same host row; unavailable/heartbeat loss does not release custody. Refused placement returns to a durable capacity queue.
- Authenticated complete Hello inventory can release missing incarnations; partial heartbeat inventory cannot infer disappearance. Event insertion and identity-fenced state effect share one transaction; matching replay is acknowledged without reapplying. Ready additionally checks epoch, module catalog and dispatcher contract. Lease renewal checks current identity and sequence; duplicate sequence preserves expiry.
- Guest lease replies must correspond to a pending request, match VM identity, exceed installed sequence, arrive before current expiry, and publish credentials successfully before extending custody. The installed bound starts at request send time, not response arrival. This is a guest cooperative bound, not host-enforced physical VM death.
- Filesystem roots are pinned descriptors; components reject traversal, symlinks, metadata and platform excludes. Mutation RPCs are serialized and cache completed outcomes; ordinary filesystem work runs on blocking threads in the dispatcher. Tree/watch traversal separately prunes ignore rules. Public live read/write/delete/rename routes do not add an ignore rule.
- Host startup defaults to libkrun and has no fallback. Merged PR #487 adds separately selected acknowledged local process mode. Host start validates exact version/identity/size/catalog/digest and retains local admission. Process-mode stop retains custody until exit proof; shutdown is bounded and restart settlement owns unfinished cleanup.
- Preview owner Close and natural exit stop the app group then execute optional cleanup with the same command builder, cwd and environment. Whole-VM lifecycle stop deliberately skips customer cleanup. The wrapper probes the configured listener before publishing readiness. Its handling of unconfirmed group reap remains an investigation target.
- Cache reads distinguish verified OCI artifacts from trusted compiled objects. Guest SCCache writes are refused, seed roots come from configured trusted platform templates, fleet lookup uses the configured organization prefix, and store publication/eviction own a maintenance lock beyond request cancellation. Per-organization IAM and producer publication were not fully inspected at this checkpoint.
- Terminal manager reattachment uses generations and retires a shell with an outstanding nonabortable old input write. Remaining wire, offset and lifecycle paths require the next pass.

## Confirmed code-bound discrepancies

**RUNTIME-001 — ignored files remain accessible through live filesystem operations.** `g5.vm.filesystem` says these operations do not work on gitignored files. `FileService::validate` only tests path safety, `.git`, staging and fixed runtime excludes; `read`, `stat`, `list`, `write`, `delete`, and `rename` never evaluate `.gitignore`. `tree` and watch-directory enumeration do. Public route `read_workspace_file_for_actor` chooses live owner reads; its sanitizer only trims leading slashes and rejects `..`. `workspace_file_save::write_live_file` checks branch association but adds no ignore filter. Fresh `FileVisibility-asbuilt` violates `NoIgnoredAccess`; the intended variant refuses ignored paths and permits normal writes. Classification: implementation divergence from explicit supplied intent; no runtime reproduction claimed. Discriminating proposed case: owner running VM with committed `.gitignore` entry and an ordinary ignored file; direct read/stat/write/delete/rename must refuse it while an adjacent product file succeeds. Test ignored directories and rename destinations independently, including later ignore-rule edits. Preserve the human text until resolved.

**RUNTIME-002 — delayed successful stop can withdraw replacement notices.** `workspace_vm_service.rs:955–1004` commits stop delivery metadata and awaits the host RPC. Independently, a host Exited event releases the old VM (`host_control_state.rs:758–833`, `release_exited`). Owner Resume can then start a replacement and create pending notices. The old successful response calls `release_stopped` in a fresh transaction; its VM UPDATE has vm/epoch/operation predicates, but `settle_after_release(Stopped)` is unconditional even if no row matched (`workspace_vm_release.rs:446–472`). The Agents auditor directly inspected `task_lifecycle.rs:4020–4079` and `chat_service.rs:690–712`: Stopped withdraws pending notices for the whole workspace with no incarnation predicate. Thus the state UPDATE is fenced but its dependent effect is not. Fresh `StaleRelease-asbuilt` finds precisely this schedule; guarded intended variant passes and permits legitimate stop and replacement completion. Classification: code-bound concurrency defect against `g5.data.identity.incarnation`; no runtime reproduction. Proposed test: hold stop reply, deliver exit, resume and queue a new notice, release old reply, assert replacement notice remains pending. `release_failed_start` has a similar unconditional settlement pattern, but its separate reachability has not been established; do not count a second confirmed defect.

**RUNTIME-003 — per-request process fork claim does not describe dispatcher filesystem RPCs.** `g5.vm.process-isolation` says dispatcher forks new processes to service API requests. `server.rs:1592–1638,1756–1762` calls `spawn_blocking` and invokes `FileService` inside the dispatcher process; the external module runner is a different boundary. Classification: explicit statement/code mismatch needing human clarification on whether isolation is intended for every request or only external module execution. Do not silently weaken the human statement or claim thread work meets process isolation. No TLA model claims to verify operating-system process separation; this is a direct architectural fact.

## Questions and proposed agent refinements

These are proposals for the parent to integrate with agent provenance, not human-provided amendments:

1. **Physical vs logical uniqueness.** Keep `g5.vm.uniqueness` intact and add a Q: should a replacement wait for independently enforced old-VM death, or is revocation of authoritative custody sufficient? Preferred production rule is host-enforced expiry/exit before replacement. `docs/worker-host-api-v9.md:375–379,419` explicitly defers host lease timers/kill to P8.14; guest expiry and control-plane identity fences do not prove a partitioned physical VM is dead. Current logical model must not be credited with physical singleton coverage. Conditional code gap pending intended boundary.
2. **Explicit local process mode.** Merged PR `20e393c0` (#487), `host.rs:39–81,465–505,560–586` establishes an explicit acknowledgment-only development mode. Propose a companion D for development scope: "Production workspace execution requires microVM isolation and never downgrades after backend failure. A deliberately selected and acknowledged local development mode may run host process groups; it is reported as such and supplies no production isolation assurance." Preserve the existing human no-fallback rule; this is a documented exception, not silent fallback. The mode is named localhost-only, but hostname/network enforcement still requires inspection rather than inference from naming.
3. **Custody and placement.** Expand human host heartbeat/slots/drain semantics in one compact agent D: "A placement reserves one current incarnation under organization quota and host capacity. Heartbeat loss prevents placement but does not release custody; drain excludes new work and completes only after all held incarnations are released. Late facts may update history but cannot release or settle a replacement." Do not repeat separate blocks for every SQL guard.
4. **Lease response authority.** One agent D: "Renewal replies extend only the current live incarnation, are tied to outstanding increasing requests, and cannot gain lifetime through delay or replay; publish the new credential before advancing the guest’s usable lease." This states the actual important guarantee while keeping cryptographic/signature and host enforcement boundaries explicit.
5. **Terminal reattachment.** Candidate pending full check: "One attachment generation controls a shell; replacement fences late input, resize and close from earlier attachments. Retire rather than reattach a shell whose older nonabortable input write can still complete." Existing human reattachment text omits this consequential rule.
6. **Cache publication accounting.** Candidate pending model: "In-flight fills reserve bounded disk space, active reads retain accounting until completion, and cancellation cannot separate cache publication or eviction from its accounting." This adds a real recovery invariant rather than enumerating cache implementation structures.

### Additional code gaps and discriminating follow-up cases

**RUNTIME-004 — preview cleanup can follow unconfirmed application termination.** The supplied `g5.vm.preview-stop` orders application stop, cleanup, then exit. `preview_serve.rs:434–458` returns `()` after logging `terminate_tokio_child` errors and discards the final group SIGKILL result. `run_preview:380–414` consequently runs cleanup and may return success. The shared terminator explicitly returns Signal/Wait/Deadline errors when reap is not established (`process_termination.rs:87–197`), so a stop attempt is not positive exit evidence. The as-built model allows a failed stop while an application remains alive, followed by cleanup; intended positive-reap gating prevents this. Classification: code-bound failure-path divergence, not an observed runtime incident. A discriminating proposed case injects a termination deadline/signal failure, verifies cleanup is not launched alongside a live process, retains failed/closing state, and allows success only after verified stop and cleanup. Also test natural shell exit with surviving descendants separately.

**RUNTIME-005 — conditional min/max autoscale has no discovered implementation owner.** Ben supplies `g5.hcp.autoscale` and organization scaling limits. `workspace_vm_service.rs:516–521` returns queued capacity for NoCapacity/QuotaExceeded without a provision trigger. Direct inspection of `ProvisionWorkerHostRequest` (`worker_host.rs:700–755`), worker-host route registration (`worker_hosts.rs:215–245`), and all cloud maintenance startup registrations (`main.rs:450–500`) finds manual provisioning, status/orphan recovery, idle/image/credential rotation and stale-host/retry machinery. Searches for autoscale/min-host/max-host settings across API/core/contracts found no such policy, corroborating those positive-path reads. Classification: **missing conditional capability**, not a claim that an unconfigured installation violates an always-on autoscaling rule. No TLA model is presented as validation of an absent capability. Proposed case: configure organization min/max, exhaust eligible slots, submit a schedulable start, observe bounded host creation and subsequent scheduling, and verify max/concurrent-start deduplication. Keep the human intent and record this implementation gap.

**RUNTIME-006 — QA fleet credentials are not scoped to one organization.** `infra/qa/platform/main.tf:238–259` assigns the default compute service account `roles/storage.objectViewer` over the entire `guest-sccache/` prefix. Hosts obtain that identity's metadata token (`cache_door/gcs.rs:10–12,60–122`). `startup_script.rs:144–180` scopes the configured reader path to `guest-sccache/orgs/<org>`, so ordinary door requests remain scoped, but the credential itself can read sibling organization prefixes. This contradicts `g5.host.cache-fleet`'s explicit organization-scoped credential clause in checked IaC. `CacheCredentialScope-asbuilt` distinguishes credential capability from the safe facade; intended scope and same-org witness pass. Classification: checked deployment-definition mismatch; live IAM and guest metadata reachability were not tested. Proposed validation uses two organization prefixes and the actual deployed host identity: own reads must succeed, sibling reads and writes must fail at storage IAM even when bypassing the facade. Do not silently replace the supplied credential rule with path filtering.

The earlier physical-singleton and local-process-scope questions remain open. Neither a lost heartbeat nor expired database custody proves a physical guest stopped. `HostAdmission` and `HostRotation` model logical custody only. Explicit acknowledged process mode has no automatic fallback; inspected mode selection contains no network-address restriction proving that the word “localhost” is enforced. It is a development exception requiring explicit scope, not evidence for production host isolation.

### Compact ontology proposals

These are **agent-inferred D proposals**, derived from the listed implementation and checked finite models; they are not additional human-provided source. Preserve all supplied I/D text. Prefer adding the following six compact blocks and attaching formal references to the existing image/cache/preview source blocks, rather than copying every guard into its own ontology block. Reattachment fences the previous generation; if an older nonabortable input write remains in flight, retire the shell instead of attaching a new owner. Replay resumes at an available byte offset and explicitly resets to the retained tail when that offset is unavailable.” Governs `g5.terminal.protocol`, `g5.terminal.reattach`; evidence `TerminalOwnership-safe`, `TerminalReplay-none`, their controls/witnesses and terminal bindings above.

- **`g5.runtime.host.rotation` (D), under host control plane.** “Rotation pairs a replacement while the old host remains available. Normal retirement waits for a ready replacement with reported slots and rechecks that the old host is idle; a credential deadline may instead force drain. Failed replacements do not silently retire the healthy old host.” Governs `g5.host.drain`, `g5.hcp.provisioning`; evidence `HostRotation-safe` is an intended fresh-custody comparison, with independent controls and retirement witnesses; actual normal-path RUNTIME-008 must be linked. Error classification and failed ownership read remain direct evidence.
- **`g5.runtime.boot.backend.process-local` (D), under host; human confirmation needed for exception scope.** “Production workspace execution uses a microVM and never downgrades after backend failure. Explicitly selected and acknowledged local development mode may use host process groups, is reported as such, and supplies no production isolation assurance.” Governs `g5.host.isolation`, `g5.host.macos`; evidence merged PR #487 and direct selector/launcher reads. This structural distinction is not a TLC proof of local-only deployment or hypervisor isolation. Retain the parent's Q if not yet authorized as an exception.
