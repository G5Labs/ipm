**Decisions the owner has not seen yet (agent choices, recorded in the plan):** raw-HTML safety is a conservative whitelist, not a proof. While rendered content follows the block (another block or the footnotes section), the raw HTML the renderer reads across the block, before and after the edit, may hold only inline and simple block elements (`BLOCK_ELEMENTS` in blockEdit.ts: p, div, details, summary, section, headings and the like; not lists, tables, select, raw-text or foreign elements) opened and closed within the same Markdown parent and nested strictly, the void elements br/hr/img/wbr and simple comments, read over the whole document; other HTML blocks get no pencil. Where earlier HTML is beyond that reading, the edited region may not change what Markdown places that would change the parser's state for the tag names that HTML mentions: tables and whether anything still renders after the block, links, task checkboxes, top-level blocks for an open paragraph or foreign content, and the region's block structure for an open heading; in place under the state at the block, in the footnotes section under the state at the end of the document. A differential test renders accepted edits through the real pipeline. Also: Ctrl/Cmd+S in the block editor = Done; pending text survives in the tab session; Save/Push/leaving Preview commit the open editor first.
