## Remaining actionable finding

### RC3-1 · P2 · Carry the selected instance prefix into personal Git credential admission

F6 now correctly applies exact origin, port and path-prefix checks to PR selection, attached repository lookup, lifecycle candidates and App-bound repository identity. The new broader GitHub instance authorization does not preserve that prefix, however: `ScmOriginPolicy::with_github_web_url` (`backend/g5-scm/src/scm_provider.rs:63–76`) discards the configured path and constructs `GitHubInstance { host, port }`; `ScmProvider::allows` checks only that origin. `AuthService::import_repos` admits the caller's clone URLs using only this origin policy (lines 2397–2408), and the non-App `RepositoryCredentials` path delegates to `ScmTokenManager::token_for_user`/`git_auth` with the same policy. The new configured instance can therefore issue personal SCM credentials to a path that its own `ProviderEndpoints::repository_name_from_clone_url` rejects as outside the selected GitHub instance prefix.

**Executed public-library counterexample:** configure `https://enterprise.test:8443/git`. Both `https://enterprise.test:8443/other/Repo.git` and `https://enterprise.test:8443/git/../other/Repo.git` return no PR repository identity, but `policy.effective_provider(Some("github"), url)` returns the configured `GitHubInstance`, and `GitAuth::scm_token_for_provider` returns `ScmToken`. The valid `/git/Org/Repo.git` control is allowed; public GitHub and wrong-port controls refuse. Receipt: `/tmp/g5-provider-final-review/reviewer3/repair/repair_probe.log`.

This is an extension-specific inconsistency between the newly tightened identity owner and the newly expanded credential owner, not a request to redesign legacy GitLab authorization. With a configured reverse-proxy prefix, an ordinary imported repository URL can select another path on that host while retaining the person's credential. App-bound PR operations have the additional identity check and do not exhibit this specific path.

**Required repair/check:** preserve the configured GitHub prefix in the trusted credential policy and in the grant carried to native/libgit2 injection, or otherwise ensure every credential-producing entry path rejects an out-of-prefix/noncanonical clone URL. Checking only the PR parser is insufficient because imports and ordinary Git operations also consume the new policy. Exercise real import and personal credential resolution for the allowed prefix, sibling prefix and dot-segment escape; assert rejected imports write nothing and refused resolution cannot emit a selected-token grant. Retain wrong-origin/port refusal and the App and public-GitHub controls. Governing: `g5.architecture.scm_credential_scopes`, `git_credentials`, `github_transport`, `g5.design.enforcement` and F6's configured-instance acceptance.

## Addendum — RC3-1 prefix repair recheck

The later repair retains `path_prefix` in `ScmProvider::GitHubInstance`. `with_github_web_url` derives it from the trusted endpoint, and `ScmProvider::allows` now checks a segment-delimited prefix after rejecting raw dot segments and percent-escaped spellings. The same provider value survives credential selection into `GitAuth`, and the existing native destination checks (`native/mod.rs`, `native/process.rs`) and libgit2 credential callback (`auth.rs::scm_credentials`) call `allows` again. The fix therefore protects both admission and use of a previously selected grant; it is not limited to the PR parser.

**Independent executed recheck:** `/tmp/g5-provider-final-review/reviewer3/repair/prefix_recheck.log` records 58 successful assertions against the current public library. It checks both policy admission and direct use of a previously selected provider grant for valid repository/protocol paths; sibling and lookalike prefixes; literal, single-escaped and double-escaped dot traversal; escaped separator; wrong port; foreign origin; userinfo; query/fragment; and an empty path beneath the prefix. Both `/git` and `/git/` configurations pass. Public-GitHub acceptance and foreign-origin refusal remain intact. No remaining counterexample was found within this bounded check.

The probe linked the SCM artifact built at **20:48:20**, after `scm_provider.rs` changed at **20:47:46**. It compiled directly with existing dependencies, used no network and changed no shared build artifacts. A source copy, probe and receipt are isolated in the reviewer directory.

The new `api_auth.rs::scm_configured_github_prefix_controls_import_and_both_personal_resolvers` exercises the real import HTTP route, `RepositoryCredentials::resolve(ReadGit)` and `ScmTokenManager::token_for_user`. It establishes actual membership and a stored encrypted personal connection, allows the configured prefixed repository, refuses sibling/dot/escaped/lookalike/wrong-port/public origins and requires no provider HTTP. Its assertions would fail under the prior origin-only policy. Invalid batches are refused before the first import lookup/write by source inspection; the test also repeats an existing provider identity, so the refusal cannot be skipped by the idempotent path. The final owner execution is still main's responsibility and was ongoing when this addendum was saved.
