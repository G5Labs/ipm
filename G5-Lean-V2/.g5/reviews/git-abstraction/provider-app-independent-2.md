## Initial finding

**P2 — preserve rate-limit evidence in the migrated repository-access check.**

`backend/g5-scm/src/providers/app.rs:299-301` maps every 403 directly to `RepositoryAccessError::AccessDenied`, before consulting the shared response's rate-limit classification. An actual call to the public `AppUserClient::verify_repository_access("owner/repo", 41)` against a localhost server returning HTTP 403, `X-RateLimit-Remaining: 0`, `Retry-After: 60`, request ID `rate-probe`, and `{"message":"API rate limit exceeded"}` produced `Err(AccessDenied)`. Thus this operation drops the newly available retry hint, request ID and rate-limit error kind.

The unchanged consumer is material: API core's `GithubAppClient::verify_user_repository_access` preserves that variant, then `auth/repository_credentials.rs:285-300` tells the initiating PR author to fix repository access/App permissions. A temporary provider limit is therefore presented as a permission failure, without the caller-decided retry evidence required by `g5.architecture.github_transport`, `git_outcomes`, and `git_retry`. This status mapping existed in the previous owner; its migration does not satisfy the newly governing error contract.

Proposed repair: in this SCM operation, handle a non-success rate-limit response through `Response::require_success` / `RepositoryAccessError::Failed(ProviderError)` before the ordinary 401/403/404 domain mappings. Preserve ordinary access-denied and connection-required results. Add public-operation controls for a matching 200, ordinary 403/404, and primary/header plus secondary/body 403 limits; verify kind, retry hint and request ID through the API-core compatibility mapping. No retry, new state or authorization change is needed.

Probe source: `/tmp/g5-provider-app-review/reviewer2/rate_limit.rs`; executable: `rate_limit` in the same directory. It links the current provider-only SCM rlib (`87772aed05649340`, built 20:03:37) and its matching Tokio dependency. Executed with localhost socket permission; output: `403 with Retry-After: 60 => Err(AccessDenied)`.
