## Initial actionable findings

### F1 — P2: executable SSH askpass stays open for writing and cannot execute on Linux

- **Path:** `backend/g5-scm/src/native/process.rs:237-262`, especially `self.credential_files.push(file)` at line 262; construction/use at lines 178-185.
- **Rule:** the approved existing-native-lease migration preserves SSH-key authentication, including encrypted keys; `g5.architecture.git_credentials` and `git_native_runner` require usable per-invocation credentials through cleanup.
- **Defect:** `NamedTempFile` owns an open read/write descriptor. Keeping that value alive for cleanup also keeps the executable askpass script open for writing. Linux refuses `execve` of such a file with `ETXTBSY`. OpenSSH therefore cannot retrieve the supplied passphrase. The old `TempSecretFile` retained only the path after its constructor's write handle closed, so this is a migration regression. macOS permits it and masks the defect.
- **Discriminating evidence:** an isolated, network-disabled `python:3.12-alpine` container with executable tmpfs created a 0700 shell script, retained its writable temporary-file handle, and executed it: `OSError(26, 'Text file busy')`. Closing the writer before executing the same file returned exit 0 and the expected text. The same open-writer case succeeds on the review host's Darwin system. This is an executable-file mechanism check, not a complete authenticated SSH push.
- **Existing test gap:** `native/tests.rs:1080` invokes askpass but its shell script does not require that invocation to succeed and later unconditionally exits 1. Its assertions require only an error category and absence of raw passphrase text. On Linux the askpass failure can satisfy those assertions; successful credential delivery is unproven.
- **Proposed repair:** close the writing handle while retaining automatic path cleanup, e.g. own a `TempPath` after writing and securing it. Require the askpass invocation to return the expected synthetic passphrase in the fixture before reporting the marker. Add a Linux case through the real native public operation with an encrypted key/local SSH fixture, while retaining cleanup-on-completion/deadline/cancellation checks.

### F2 — P2: validate the normalized transport after GitHub SSH identity conversion

- **Path:** `backend/g5-scm/src/native/mod.rs:369-379` and `395-396`.
- **Rules:** `g5.architecture.git_ref_updates`, `git_credentials`, and the native-migration design require the actual destination to match the requested repository, including rejecting ordinary configured URL rewrites.
- **Defect:** `check_remote` validates the original SSH identity, then `auth.transport_url` converts it to an HTTPS URL. The command pushes that newly constructed URL without checking Git's expansion of it. An `url.<other-destination>.insteadOf=https://github.com/review/repo.git` entry is invisible to the earlier SSH-identity check and redirects the actual push. The operation then reports `Ok(Updated)` for the requested identity even though another repository received the effect. URL-scoped headers avoid sending the token to the local-file destination used by the proof; no token leak is claimed.
- **Public-path evidence:** a standalone driver linked to the current built `g5-scm` called `NativeGit::push_branch_blocking` with `GitAuth::Token`, `expected_url=git@github.com:review/repo.git`, source `main`, and a create-if-absent lease. The isolated repository's origin retained that SSH identity. Its config mapped the normalized HTTPS URL to another local bare repository. `git remote get-url --push --all origin` returned the exact expected SSH identity; `git ls-remote --get-url https://github.com/review/repo.git` returned the local file URL. The native call returned `Ok(Updated)`, and the other bare repository acquired `refs/heads/main` at `900478d154d65899005c4ba6174d1c78857722d2`. No network or real credential was used. Driver and fixture are under `/tmp/g5-lease-review2/`.
- **Attribution:** legacy `GitRepo` already normalized this transport; the current increment brings that variant into the shared native operation after its destination check. This is a violation of the migration's promised effective-destination boundary and a newly accepted variant of `NativeGit`, not a claim that the legacy code previously enforced this boundary.
- **Proposed repair/check:** validate the normalized URL through `check_expansion` before credential injection/push, preserving the trusted guest relay variant. Add the public-path fixture above for both normalized GitHub SSH forms and assert `FailureKind::Destination`, `FailureEffect::Refused`, and unchanged refs in the alternate repository. Preserve successful normalization with canonical origin unchanged.

### R2-F2a — P2: tied push rewrites can still redirect a normalized operation

At `backend/g5-scm/src/native/mod.rs:698-702`, the flat config scan retains the first matching maximum-length entry. Git groups rewrite entries by their URL base, retaining the order of first occurrence of each base. Consequently, these effective entries cause the new validator to choose the identity mapping while Git chooses the alternate destination:

```gitconfig
[url "/tmp/alternate.git"]
    pushInsteadOf = https://unmatched.invalid/
[url "https://github.com/review/repo.git"]
    pushInsteadOf = https://github.com/review/repo.git
[url "/tmp/alternate.git"]
    pushInsteadOf = https://github.com/review/repo.git
```

This can also arise from configuration split across included/global/local sources; it does not require an invalid Git config. The first alternate-base entry is unmatched but establishes Git's base order. When the same base later receives a prefix equal to the identity entry, Git gives that earlier base the tie.

**Discriminating check:** a scratch driver compiled the exact current `native/mod.rs`, `native/process.rs`, `native/cancellation.rs` and `auth.rs` sources, linking cached workspace dependencies. With an origin of `git@github.com:review/repo.git`, the effective config above, and a create-if-absent lease, its public `NativeGit::push_branch_blocking` returned `Ok(Updated)`. The alternate bare repository gained `refs/heads/main` at `c9075bb647fcd57767dc68ba712182c16cc77a16`. `git remote get-url --push probe` for an independently configured HTTPS probe remote confirmed Git's alternate destination. The fixture is `/tmp/g5-lease-review2/tie-btib5jxm`; the source-linked driver is `/tmp/g5-lease-review2/repair_probe.rs`. No actual provider or real credential was involved.

**Minimal repair:** handle tied longest candidates safely. Either reproduce Git's first-base grouping exactly or refuse an ambiguous maximum-length set containing any nonidentity mapping. Continue ignoring strictly shorter mappings so the legitimate longest identity fixture remains valid. Add the repeated-base case above through the public native push/delete paths and assert a destination refusal with unchanged alternate refs. No public API, state, recovery mechanism or ontology meaning change is needed.
