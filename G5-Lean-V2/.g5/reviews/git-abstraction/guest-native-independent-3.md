## Initial findings (saved before sharing)

### F1 — P1: dispatcher unit-test target no longer compiles

`backend/g5d-dispatch/src/git.rs:552` still calls `set_mode(&hook, 0o700)`, but this increment removes the helper from production configuration installation. `cargo test -p g5d-dispatch --lib --offline` fails with E0425. This blocks the crate's configuration/credential regression suite and workspace test builds; successful normal dependency builds do not cover `cfg(test)`.

Fix: retain a test-local permission helper or set the fixture's permissions directly. Regression: build and run the full dispatcher lib-test target. Evidence: `/tmp/g5-guest-review-3/dispatch-unit.log`.

### F2 — P2: unavailable HEAD can panic Update and strand module admission

The new `MemberParentUpdate` assembly at `backend/g5d-dispatch/src/modules/builtin.rs:809–812` uses `report["head_oid"].as_str().expect("validated association")`. Association at lines 522–563 does not add an error when the HEAD observation failed: it validates symbolic branch/tracking/sequencer observations but leaves `head_oid = null` compatible with `errors = []`.

Concrete Git preconditions were reproduced under `/tmp/g5-guest-review-3/missing-head`: create an empty commit on `shared`, preserve its OID in `refs/remotes/origin/shared`, then delete `refs/heads/shared` with `git update-ref -d`. `symbolic-ref --short HEAD` still returns `shared`; tracking lookup and Git-directory observation succeed; `status --porcelain -z` succeeds with an empty result; `rev-parse --verify HEAD` fails. With an upstream and transport available this reaches the new `expect` and panics rather than returning a failed Update. The spawned module runner calls `finish` only after normal return (`modules/mod.rs:701–715`), while its mutation permit remains in the execution record until `finish` (`modules/mod.rs:838`), so a panic can retain admission and an unfinished invocation.

This violates explicit/refused outcomes and bounded runtime operation/drain obligations (`g5.architecture.git_outcomes`, `g5.runtime.operations-identity`, `g5.runtime.drain`). Fix: classify a missing/invalid HEAD as association failure and avoid an unchecked expectation at the adapter boundary. Regression: invoke real workspace Update against the above state, assert a terminal failure, then prove a new operation/drain can proceed. Evidence level: real-Git preconditions plus traced Rust control flow; the complete dispatcher RPC reproduction was not executed in this review.

### F3 — P2: public switch-back operation interprets an admitted ref name as a Git option

`backend/g5-scm/src/native/member/transport.rs:216` passes `branch` directly to `git checkout -q`. `MemberGit::check_branch` at `member.rs:348` checks `refs/heads/{branch}`, which accepts `-f` as a full ref name. With existing `refs/heads/-f` and `refs/remotes/origin/-f`, `MemberGit::switch_back(root, "-f")` runs `checkout -q -f`, discards an unstaged edit on the current branch, returns success, and never switches to the requested ref.

An external Rust probe calling the actual public `MemberGit` operation confirmed `result=Ok(false) branch=shared file="saved\n"` after the file contained `unsaved\n`. See `/tmp/g5-guest-review-3/probe.rs` and `option-probe.log`. The current dispatcher separately rejects option-like branches, so this is an exposed SCM-boundary defect rather than a claim that its current `switch_back` adapter admits the counterexample. It nevertheless defeats the new typed operation's promised scope and permits destructive effects absent from the declared request (`g5.architecture.git_ref_updates`, `g5.architecture.commands`, `g5.design.enforcement`).

Fix: validate branch-short-name/argument safety inside SCM (including leading `-` and shorthand semantics) and construct checkout arguments that cannot be interpreted as options/pathspecs. Regression: public operation refuses option-like names without changing HEAD, index, or worktree, while ordinary names remain allowed.
