## Initial findings

### F1 — P2: Post-acceptance SQL failures can discard the new confirmed-effect result

- **Paths:** `backend/g5-api-routes/src/routes/git.rs:681`, `:685`, `:695`, `:698`, and the new failure dispatch at `:749`.
- **Counterexample:** Native receive-pack has emitted `ok refs/heads/<workspace>` and then exited unsuccessfully. SCM correctly returns the acceptance plus `failure: Partial`. Before the API reaches the new `output.failure` branch, `admission.commit`, scoped database acquisition, enqueue, or enqueue commit fails. The `?` returns a generic `GitError::Internal`; its HTTP body is only `internal error`. The authoritative acceptance and process failure are both lost from the response, and enqueue failure prevents that confirmed ref's branch event and the later reviewer notifications. Failure on one accepted ref also skips later accepted refs' independent continuation.
- **Consequence:** A client cannot distinguish this accepted push from a failure before effects or identify the required manual publication recovery. A database interruption on the newly supported “acceptance followed by process failure” path defeats the advertised outcome guarantee.
- **Governing:** `g5.architecture.git_outcomes`, `git_ref_updates`, `git_retry`, and `pr_flow`; pinned protocol design says captured acceptance survives execution failure and known effects retain their existing continuation.
- **Scope qualification:** The generic SQL `?` exits existed at HEAD. This is a material conformance gap in the reused continuation that the new process-failure path now enters, rather than a newly introduced SQL regression. I have not counted unrelated pre-existing publication issues as findings.
- **Recommended repair:** Preserve the confirmed-ref vector and native failure while attempting the existing continuations. Convert post-effect failures into a redacted Partial result naming completed refs, failed stage and manual Update PR/current-ref inspection guidance. Keep independent confirmed-ref signals and later siblings from being discarded solely because one enqueue failed; release admission before independent SQL as today. Add no retry worker or persisted state.
- **Discriminating regression:** In an isolated API test, perform a real admitted ref update, make the configured Git wrapper fail after its acceptance report, and inject a failure in that push's existing enqueue/commit stage. Verify the real ref moved, the response still identifies Partial/accepted refs and the failing continuation, and independent confirmed-ref events/siblings are handled. Also test the same SQL failure after a normally successful Git process. Source inspection establishes the early-return defect; this combined runtime failure was not injected during discovery.

### F2 — P3: The new ordering guard accepts comments and rejects harmless call formatting

- **Path:** `backend/g5-api/tests/route_auth_static.rs:835` (`required_git_guards_precede_effect`), used at `:818` and `:850`.
- **Evidence:** Exact copies of this helper and its two source helpers were compiled into an isolated Rust test executable. A body containing only `/* guard .receive_pack(&repo_path, decoded_body, &admitted) */` is accepted. A real call with the same method/arguments formatted on separate lines with a trailing comma is rejected. Both discriminating assertions failed, as expected for the defect. The current tests' `replace` controls remove every matching string, including comments, and their harmless control is synthetic text rather than a Rust invocation.
- **Consequence:** The promised missing-effect check can be satisfied without an executable effect or authority check, while ordinary formatting/argument renaming breaks the guard. This weakens the newly added regression protection; it does not establish a current authorization bypass in production.
- **Governing:** `g5.architecture.git_guard`, `g5.quality.review.guards`, `g5.quality.review.cases` and the pinned protocol guard requirement.
- **Recommended repair:** Recognize the relevant calls in parsed Rust syntax, excluding comments/string contents and comparing operation identity independently of exact argument formatting. Retain explicit missing-effect/missing-guard and effect-before-guard controls. Full control-flow proof is not required for this structural guard.
- **Discriminating regression:** Use actual Rust function fixtures for commented-out guards/effects, multiline calls, renamed local arguments and private helpers, absent calls and reordered executable calls.
- **Receipt:** `/var/folders/yf/bc92js5n0bjg59_gc7ztxqjr0000gn/T/g5-review3-guard-thidg4sf/exact_guard_helpers.rs`; executable beside it. These scratch files contain exact copied helper bodies plus the two additional review-only tests.

## Post-repair recheck — F1 continuation handling

This bounded read-only recheck followed the main agent's saved consolidation and repair. The initial findings above remain unchanged as historical evidence. Scope: current `receive_pack_owned` continuation handling and the new public API publication-failure regression; no delegation, production/test edits or competing integration run.

**Source disposition: F1 repaired.** In `backend/g5-api-routes/src/routes/git.rs:681–770`, admission release and each publication operation now record failure instead of returning through the old generic `?` exits. After successful admission release, each accepted branch gets one independent publication attempt, and failure does not exit the loop. The branch event is published outside that fallible operation. Admission-release failure prevents further independent SQL, including reviewer-notification SQL, while retaining the confirmed in-memory branch hints. No retry or persistent recovery mechanism was added.

The resulting continuation error carries the confirmed-ref vector, Partial when an acceptance is known and Unknown otherwise, the failed continuation stage, available native completion/observation detail, and current-ref/Update PR recovery guidance. The earlier `output.failure` path can therefore no longer be erased by the repaired SQL exits. This recheck found no further defect in those changes. The existing ordering rule remains intact: independent SQL follows successful admission release.
