## Initial findings

### R1-F1 — Initial-file preparation does not validate its complete exact-file batch (P2, inherited implementation gap in the moved capability)

**Path:** `backend/g5-scm/src/commit_preparation.rs:419–445`, especially `validate_isolated_files` at 219–257 and the subsequent `Index::add` loop. Compatibility re-export: `backend/g5-workspace-ops/src/commit.rs:26`.

**Commitment:** the workspace-operations design requires complete validation/path behavior and invalid batches rejected before object writes; `g5.architecture.commands` and `g5.design.minimal-api` require the exposed operation to preserve its own invariants. The public request promises an unattached parentless commit containing exact files.

**Counterexamples, executed through the actual public `g5_scm::prepare_initial_files_commit` against the current cached library:**

1. Files `[("a", "ancestor"), ("a/b", "descendant")]` succeed, but `git ls-tree -r <candidate>` contains only `a/b`. Libgit2 replaces the earlier colliding index entry. The operation reports a successful exact-files candidate after silently dropping requested content.
2. Files `[("okay", unique_bytes), (".git/config", other_unique_bytes)]` fail only during index insertion, after both blobs have been stored. `git count-objects -v` in the newly created bare repo reports two objects. This is an invalid-path batch that writes objects before refusal.
3. `[("a//b", "double")]` passes the path validator and fails while writing the tree, leaving two objects.

Scratch source/output: `/tmp/g5-reviewer1/probe.rs`, `/tmp/g5-reviewer1/probe-output.txt`; each fixture repository is isolated beneath that directory. The library used was `target/debug/deps/libg5_scm-d0a5004204312319.rlib`. These are implementation observations, not a model.

**Scope qualification:** normalized function comparison proves this behavior is inherited unchanged from `7054bdfb`; the refactor did not introduce the bug. The sole current production initial-files caller, `WorkspaceService::initialize_local_workspace_repo`, supplies the fixed path `README.md`, so these counterexamples are not presently user-triggerable through that caller. Nevertheless, this is the migrated public preparation capability whose validation the saved design claims to preserve, and it is a concrete gap in its contract. Exact-base tree preparation already validates these cases correctly. Do not characterize the whole migration as causing existing data loss.

**Proposed repair:** validate initial paths/collisions completely before calling `repo.blob`, using the existing exact-tree canonical-path and ancestor-collision validation while preserving the initial-files operation’s explicit `.g5` restriction and parentless semantics. Add initial-preparation cases for ancestor collisions in both orders and valid-first/invalid-later batches, asserting no new blob object and unchanged refs/index/checkout. Retain the valid `README.md` bootstrap and literal-path cases. No retry or new state is needed.

### R1-F2 — The new privacy checks guard three names, but do not ratchet public backend type exposure (P2, safeguard coverage gap)

**Paths:** `backend/g5-scm/src/lib.rs:29–39`; `backend/g5-api/tests/authoritative_workspace_reader_guard.rs:143–256,387–405`.

**Commitment:** `g5.architecture.git_guard`, `g5.quality.review.guards`, and the increment’s explicit requirement to extend public-interface guards. Production dependency/source closure and public-interface closure are separate obligations.

**Evidence:** the compile-fail checks correctly reject `from_raw`, `lock_inner`, and `configure_callbacks`, and current source inspection found no remaining public raw backend handle. However, those tests would still pass after adding an equivalent escape hatch under another name. `typed_git_violations("g5-scm/repo.rs", "impl GitRepo { pub fn raw(&self) -> &git2::Repository { unimplemented!() } }", &[])` reports no violations: SCM is intentionally exempt from the production backend check, and this guard checks native spawning rather than public signatures. The exact implementation was compiled in isolated `/tmp/g5-reviewer1/guard.rs` with an additional probe; its initial probe used `&self.inner` as an illustrative body (the source guard is syntactic), and returned `raw_handle_violations=[]`. The signature-only counterexample does not depend on the body. New callers could then use inferred backend values without adding their own direct `git2` dependency, so the dependency check would not recover this boundary.

**Consequence:** the currently removed APIs are private, but a newly named raw repository/index/callback return or callback input is not rejected by the new ratchet. This is missing requested regression enforcement, not a presently observed production escape hatch.

**Proposed repair:** add a public-interface check over exported SCM operations/types, resolving backend aliases/re-exports sufficiently for the repository’s structure. Calibrate it with a newly named raw handle getter, backend callback argument/type alias, a missing expected target where appropriate, and harmless private backend helper/type refactors; keep positive external use and the existing compile-fail examples. Do not ban private backend usage inside SCM.
