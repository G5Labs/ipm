## Initial findings

### F1 — P1: check failures can expose a configured secret cut by the transport diagnostic limit

Affected locations: `backend/g5-scm/src/providers/checks.rs:39–54`, `providers/transport.rs:204–214,247–269`, and `providers/pulls.rs:117–127` (the private request helper supplies an empty extra-secret set). The authorized API check owner supplies its effective configured secret values, but SCM only applies those values after transport error construction. The transport first scrubs the selected provider credential and caps each diagnostic field at 1,024 characters. A configured secret crossing that boundary is already incomplete when `checks.rs` tries exact replacement, so its retained prefix escapes into `ProviderError` and the API's public `message`. The same ordering affects the diagnostic-error path that calls `CheckReader::clean` on an already constructed error.

This is introduced by migrating checks from a status-only HTTP failure to provider diagnostic text. It violates `g5.security.credentials.redaction`, `g5.governance.pr.checks.details`, and `g5.architecture.git_outcomes`.

Independent public-operation probe: `/tmp/g5-provider-final-review/reviewer1/check_secret_probe.rs`, with output in `check_secret_probe.log`. It calls the actual compiled `RepositoryClient::read_pull_request_checks` against a local HTTP 403 stub. The configured value is `SCOPED_CONFIG_SECRET_abcdefghijklmnopqrstuvwxyz`; the error body places it after 1,000 `x` characters and a space. The resulting public error ends its message with `SCOPED_CONFIG_SECRET_ab`, and the probe prints `leaks_configured_prefix=true`. The selected provider token is different. This is a configured-secret prefix, not an accidental match against the selected bearer token. The API check owner's `ReadFailure` and JSON projection preserve this error text; that propagation was inspected, not separately fault-injected through the HTTP route.

Proposed repair: give the check operation's complete redaction set to transport before diagnostic extraction/capping, or defer truncation until all owner-provided redaction has completed. Cover message and provider headers, including annotation failures. Add a public-operation regression placing a secret across the cap and a control showing useful nonsecret retry/request evidence survives.

Artifact freshness: the probe links read-only `target/debug/deps/libg5_scm-cb95f83459e19a0f.rlib`, timestamp 20:29:36, rebuilt by main after the snapshot. Relevant source timestamps are checks 20:20:51, transport 20:26:41, pulls 20:28:17. Its source set matched the snapshot. The initial local bind was sandbox-denied; the same isolated probe then ran with reviewed local-loopback permission. No production request or credential was used.

### F2 — P2: the whole-backend guard exempts every SCM file from shared-transport enforcement

Affected location: `backend/g5-api/tests/authoritative_workspace_reader_guard.rs:2090–2093`. `provider_http_violations` returns no violations for any `g5-scm/` path. Consequently, a new public SCM operation can construct its own `reqwest::Client`, send a selected credential to a configured URL, and bypass both the scoped provider clients and their shared redirect/retry/redaction transport. The separate public-interface check only rejects exposed backend types, so it does not catch an owned-signature operation doing raw HTTP internally.

This violates the explicit guard obligation in `g5.architecture.git_guard` and the plan's “raw provider HTTP outside permitted typed clients/transport” case. SCM is the intended crate owner; that does not make every future SCM module a declared provider transport. The current production inventory does use the shared transport; this is a demonstrated guard false negative, not a claim that the current implementation already contains the injected bypass.

Independent calibrated probe: `/tmp/g5-provider-final-review/reviewer1/provider_guard_probe.rs` copies the frozen guard source and appends one isolated test, compiled directly with existing dependencies. A public `bypass(token: &str, configured_url: &str)` that calls `reqwest::Client::new().get(configured_url).bearer_auth(token).send().await` is rejected under `g5-new-crate/reader.rs`, but accepted under `g5-scm/new_reader.rs`; `scm_public_backend_violations` also accepts its public signature. Output is in `provider_guard_probe.log`. No shared guard source or source fixture was mutated.

Proposed repair: distinguish SCM's declared typed adapters and private transport from unrelated SCM modules, and restrict raw client construction/delivery to the shared transport. Retain legitimate endpoint payload/method assembly in the typed clients and allowed private helper refactors. Add the SCM sibling bypass, an in-adapter alternate-client bypass, and positive shared-transport/private-helper controls.
