# Entra identity proof

[Issue #1101](https://github.com/G5Labs/G5-Lean/issues/1101) authorizes the backend security correction and explicitly excludes onboarding. The owning changes are [login proof](../../ontology/features/users.g5.md#g5.user.login-proof) and [login providers](../../ontology/features/users.g5.md#g5.user.login-providers). Unchanged [admission](../../ontology/features/users.g5.md#g5.user.admission), [invitation authority](../../ontology/features/organizations.g5.md#g5.organization.invitation-authority), [service identity](../../ontology/features/organizations.g5.md#g5.organization.platform-operator.bootstrap) and [session authority](../../ontology/features/users.g5.md#g5.user.session-authority) govern the result.

The Entra adapter owns token verification, using the existing JWT library and a tenant-scoped signing-key cache. Require a directory UUID so the configured tenant can be compared directly to `tid` and the exact v2 issuer. Keys come only from the configured tenant's published endpoint (or an explicit deployment override for tests); token headers cannot choose a key source. Cache one key set per client, refresh after one hour or an unknown key, and serialize and rate-limit refresh attempts to once per five minutes. An expired cache or unavailable required key fails closed. This bounded cache avoids per-login network fetches and unbounded attacker-selected key entries. [Microsoft's rotation guidance](https://learn.microsoft.com/en-us/entra/identity-platform/signing-key-rollover) informs the refresh policy.

Reuse the existing cryptographically random, persisted OAuth state as the OIDC nonce. Its browser binding, provider check, expiry and atomic deletion already own single-use admission, including concurrent callbacks. A second nonce record would duplicate that lifecycle without adding a guarantee. Consume the attempt before exchange; invalid proof, exchange failure or cancellation requires a fresh attempt. Verify signature, issuer, tenant, audience, expiry, not-before and nonce before exposing identity claims. Remove userinfo and unverified JWT decoding entirely.

The login service receives an immutable Microsoft identity serialized as canonical `tid:oid`, with no verified emails. It matches only that existing identity and preserves the account email even if the display hint differs or is absent. No Microsoft callback can create an account or accept an invitation. GitHub retains its verified-email linking. Lock account candidates through the update transaction and reject service rows before mutations. Recheck and hold a membership of the locked Microsoft account through commit so a concurrent relink or removal cannot substitute admission proof; account linking and invitation acceptance retain their shared transaction. Failed or ambiguous proof issues no session and changes no accounts, memberships or invitations.

Clear legacy Microsoft provider/id pairs in a counted migration; preserve other providers. The dated no-Entra-use assumption belongs to the owning provider metadata and explains why no credential revocation is needed. This is intentionally unusable for new Entra people pending a separate product design.

Verify signed-token rejection for invalid signatures, algorithms, issuer, tenant, audience, time claims, absent or mismatched nonce, and missing identity; exercise key caching, rotation, expiry and failure. API tests must show nonce replay and concurrent consumption refusal, email collision with GitHub/service accounts and invitations without mutation, service refusal through GitHub, and successful existing-pair login despite a changed or absent hint. Exercise the migration on seeded Microsoft and GitHub rows, then run the existing auth integration suite and required CI. No live tenant is available; signed local issuer fixtures establish the backend contract.
