# Stop VM after merge

Status: the owner authorized immediate API-side Stop after `merge_pull_request_as` succeeds, replacing the delayed execution design, and extended it to direct Ship to parent (2026-11-09). The owner then approved the setting above the shipping options with a short scope hint. The owner also approved a personal default in Settings → Execution policy before Idle timeout (2026-11-10). The personal-default extension is implemented and locally verified; its current validation is recorded first below, followed by historical evidence for the earlier revisions. Published CI/reviews are tracked in [PR #1162](https://github.com/G5Labs/G5-Lean/pull/1162).

## Intent and governing statements

The [owner's request](../../chat_intent/stop-vm-after-auto-merge/request.md#ship-to-parent-revision-2026-11-09) shares one optional setting across Ship to parent, Ship with agent and Merge when ready, without a delay. The owning statements are [optional VM stop](../../ontology/software_architecture/git.g5.md#g5.git.pr-auto-merge.stop-vm) and the [selected setting UI](../../ontology/features/ui.g5.md#g5.workbench.ship-to-parent.stop-vm). Existing [human merge consent](../../ontology/software_architecture/git.g5.md#g5.git.pr-auto-merge), [shipping controls](../../ontology/features/ui.g5.md#g5.workbench.ship-to-parent), [current-owner authority](../../ontology/software_architecture/workspace_vm.g5.md#g5.security.owner) and [ordinary Stop](../../ontology/software_architecture/workspace_vm.g5.md#g5.lifecycle.stop) govern the integration.

## Choice and UI

The [approved layout](../../chat_intent/stop-vm-after-auto-merge/request.md#shared-setting-layout-2026-11-09) puts the dedicated setting above both shipping buttons, in a shared bordered group with Merge when ready below the buttons. The setting row is lightly shaded, with the exact helper “Applies to all merge options below.” and no forced line break. The [approved personal default](../../chat_intent/stop-vm-after-auto-merge/request.md#personal-default-2026-11-10) lives in Settings → Execution policy before Idle timeout, with “Default for all your workspaces. You can change it in Prepare to Ship.” It is initially off and belongs to the person across organizations, including when no workspace is selected or the person does not own the current workspace; only Idle timeout stays workspace-gated. The control saves immediately, disables during loading/saving and reports failures inline. Changing the setting enables neither merge nor an agent, and a failed agent launch rolls back a submitted setting change. Ship to parent waits for the setting to finish saving before accepting a click.

The user profile owns one new `stop_vm_after_merge_default` boolean, exposed through the existing person-session-only profile read/update. Browser-local preferences cannot supply a server merge, and organization-scoped runtime configuration does not express the account-wide choice. The PR keeps its existing `stop_vm_after_merge` field: null inherits the current source owner's default, while either boolean is an explicit choice. An explicit choice equal to the current default still has to be stored. Existing saved values remain overrides on upgrade because the old field carries no evidence distinguishing an intentional false from the old default; new PRs inherit. No per-workspace preference copy, scheduling state or additional lifecycle is needed.

The PR owner resolves the effective choice for every summary and all three shipping paths. Its successful merge transaction fixes the effective value in the same existing field, so a later profile change cannot alter a completed merge. The common Stop follow-up uses that fixed choice. Setting an override and transfer keep the existing source-workspace lock: transfer resets unmerged choices to inheritance from the new owner, but fixes merged choices off to prevent stopping the new owner's VM for an old merge. Other authorized people may enable automatic merge without changing the source owner's choice; their own default never participates. A choice cannot be edited after merge.

The new migration adds the user field and makes the existing PR choice nullable, preserving all existing values. Tenant connections cannot read global user rows: the PR service derives source owners through its scoped transaction, then the identity service reads only those owners' defaults on the system connection. This keeps profile permissions unchanged and is tested under the real tenant role. Profile patches update only supplied fields in one statement, so saving the default cannot restore a stale name/avatar or lose a concurrent preference change. The client refreshes PR summaries after saving its default; no cross-owner bulk write is introduced.

## Execution and failure boundary

The shared successful merge path checks the choice and dispatches the ordinary owner Stop in an async task, so direct Ship to parent and both automatic paths have the same behavior. The task rechecks the fixed choice with the source's current owner and uses the PR ID as its operation identity. Saving and shutdown do not hold up the merge response or shared merge scan. The VM lifecycle owns admission, saving, retries after admission and physical shutdown; Git stores no deadline, VM binding or stop completion record. Failed merges and cancelled automatic shipping invoke no stop. A direct merge still honors the setting if Merge when ready was turned off.

The merge's existing announcement precedes Stop. A stop error is logged without turning a committed merge into a failed merge or scheduling another merge attempt. This immediate follow-up has no separate durable handoff: an API exit or failure before Stop admission can leave the VM running; admitted stops retain the existing lifecycle's recovery. This is the reduced operating guarantee of the requested simplification, and replaces the previous restart-safe PR scheduling assumption.

Ship with agent uses the same automatic merge path. Its selected prompt explains that the API handles immediate shutdown; it issues no second stop command that could outlive a withdrawn choice or restart. The normal manual command remains `/bin/bash -lc 'g5d workspace stop'`; no new CLI option is needed. [Start and ship with agent](../ship-with-agent-wo-vm/ontology-plan.md) keeps its Start consent, chat binding and withdrawal rules.
