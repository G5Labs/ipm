## Contract and ownership

[Membership](../../ontology/features/organizations.g5.md#g5.organization.membership) has exactly Admin, Member and Viewer. Existing organization Owners become ordinary Admins in place, retaining identities, activity, additive grants, credentials, workspace/Base ownership and history. No ownership-handover lifecycle is introduced. Former Owners follow ordinary Admin offboarding, with existing self-action, workspace-transfer and cleanup requirements.

[Administrator continuity](../../ontology/features/organizations.g5.md#g5.organization.ownership) belongs to OrgService's complete membership transition. Supported tenant creation establishes an active Admin. Removal, demotion and deactivation cannot remove its final active Admin; only an Admin membership with no deactivation timestamp counts. Invitations, additive grants and inactive Admins do not count; execution holds do not remove activity. The operator bootstrap/recovery exception and whole-organization deletion remain valid.

PermissionService owns current authority; PersonalWorkspace owns retirement through the identity-owned interface installed by the composition root. Their durable effects share the membership transaction. The continuity decision precedes every membership, retirement, hold and access change. A nested transaction rolls the complete operation back on any error or cancellation, including if its caller later commits; runtime stopping and access delivery remain after outer commit. Workspace ownership, fixed audiences and resource limits remain separate contracts.

## Concurrency and supported writers

Acquire the organization before actor/target memberships in UUID order, then reauthorize current membership and decide the surviving Admin set. Updating the existing organization row without changing its access-generation value provides a serialization point: READ COMMITTED reads the committed membership set after waiting, while a stale REPEATABLE READ or SERIALIZABLE transaction must abort. Bounded whole-transaction retries repeat admission. Existing generation-bump triggers remain authority infrastructure, not the policy decision.

Every supported administrator-reducing application writer must call this operation. Creation and additive provisioning establish Admin without reducing the existing set. Dev persona role convergence must use the member API, including reruns. Audit user deletion and cascades; any supported account-deletion operation must coordinate affected organizations through the same owner before deletion. Privileged manual SQL, repair and test fixture setup bypass application enforcement and must validate their intended final state; no database continuity guarantee is claimed.

The writer audit found no supported hard-user-deletion route/service/CLI; raw user deletion can cascade memberships and is outside this contract. OrgService's role/activity/removal writers are private to `change_member`. Tenant/platform creation, invitation acceptance, test-token provisioning and operator bootstrap insert memberships without reducing existing Admins. CI/service/workspace seeds only insert or promote; self-hosted bootstrap's atomic creation/promotion preserves activity on reruns. Reset recreates whole organizations through creation, and dev persona reset now calls the guarded API. Stop/cleanup writers change execution holds only. Future account deletion must join the shared organization transition before gaining a supported API.

Dev persona seeding provisions the declared roster before converging roles and applies declared Admin roles before reductions. Each reduction uses a known fixture identity that currently has Admin authority and will retain it, including when the roster demotes the fixture operator. The selected session is refreshed for the target organization so its issued scope ceiling reflects current authority; the mutation still rechecks authority in the guarded application operation. Reruns select current authority again. Missing authority is a refusal, never a reason to mint an arbitrary replacement identity, reactivate a person or repair membership roles through SQL.
