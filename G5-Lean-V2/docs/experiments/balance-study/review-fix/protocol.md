## Execution and preservation

Use fresh local Git repositories with no remote or inherited history. Runtime directories,
PostgreSQL clusters, Redis instances, frontend dependencies, build outputs and temp paths
are private. Warm dependencies are cloned and every workspace package is cleaned. All
workers get two Cargo jobs and one integration test thread. No real provider/guest is
available. Independent evaluation runs in a separate reserved copy. Each run starts from
the same snapshot and clean service data. Never reset a worker or the maintained checkout.

Dispatch three balanced waves with one run per condition: normal/old/revised, then
revised/normal/old, then old/revised/normal. This is counterbalancing, not random allocation.
No arbitrary short cutoff, no known-defect hints or mid-run evaluator feedback. A worker
may ask for infrastructure help; disclose interventions and preserve their cost. Worker
budgets/settings are identical. Shared host and wave effects limit elapsed-time comparisons.

Before any production repair, workers save `initial-findings.md` and invoke a common
checkpoint helper that commits and freezes that report, source patch, timestamp and hash.
Investigative tests may precede the checkpoint; source edits are audited for early repairs.
Later discoveries are separate. A final checkpoint preserves repairs, verification and
remaining gaps. Preserve public actions, usage, prompts, input hashes and exact commands;
exclude private reasoning. Neither report agreement nor a worker's claimed fix is verification.

## Frozen evaluation

Use the original I1–I8 outcome contract: graph/input/lineage correctness; original history;
idempotent/conflicting/concurrent submissions; invalid graph/input refusal and rollback;
current authority/admission without implicit Start and historical read replay; accepted
launch plus current eligibility; owning module allocation/settlement/cancellation; and
existing UI submission/recovery/progress. All outcomes matter even if not in a known-bug list.

Independently apply the unchanged final 12 prior API/database/dispatch tests, first to the
untouched baseline and then each final delivery. Retain exact probe hashes and receipts.
Known diagnostics: accepted-model drift, valid future nudge admission, job concurrency cap,
and substantive TaskService ownership of task/first-input validation/allocation (source
assessment, not a thirteenth test). Also inspect lost-response/reload identity recovery and
the ordinary progress synchronization consumer. Count unique causal defects, not report
bullets or test functions, and accept supported new findings beyond these targets.

Preserve allowed cases: unchanged launch dispatch, an already accepted receipt after VM
stop under current read permission, new work during a valid future nudge, original history
and success reuse, independent intentional submissions, ordinary cancellation of the new
graph, and normal module-owned allocation in one transaction. Fixes must not accidentally
prohibit these cases. Frozen tests include several such controls. Added source-directed
checks must be labeled adaptive and use the same semantics for comparable candidates.

For each run report initial vs later detection, supported new findings, unsupported or
overstated claims, actual repair success, residual defects and introduced regressions.
Distinguish new regressions from inherited defects and unfulfilled feature obligations.
Adjudicate against full caller/consumer paths and governing outcomes. A compiler failure
or evaluator fixture error is not itself evidence of the target product defect. Preserve
failed attempts; fix evaluator errors explicitly, never change requirements to fit code.

For retrieval, record observable reads of governing body text separately from mere ID
searches or availability. For application, require an actual report/check/source trace that
uses the rule. Retrieval without a finding is not necessarily failure where no defect exists.
Absent observable retrieval is not proof of absence from model context or implicit reasoning.

Astra audits protocol, independently inspects de-identified source/findings where feasible,
and adjudicates evidence. Withhold condition mapping and skill artifacts from that inspection;
report inferred/unavoidable unblinding. The preparing supervisor knows conditions and targets.
Record worker review/repair elapsed and cumulative/output/reasoning token accounting separately
from Astra preparation/evaluation and infrastructure. Wall time includes tools/waits; no dollar
cost or model efficiency estimate without actual billing data.

## Limits and subsequent selection

Nine runs on one previously studied feature are a pilot, not a population reliability rate.
No real browser journey, provider execution or exhaustive concurrency certification follows
from the existing probes. Scoped source evidence and runtime evidence are reported separately.
Filesystem isolation is by distinct directories and explicit instruction, not a sandbox;
ambient tool/skill descriptions and parent cwd may still appear. Audit visible reads for leaks.

After all nine runs, choose the next most informative bounded experiment from observed
failure modes: included rule text if retrieval fails; equal-budget additional review if
coverage varies; outcome checkpoints if fixes drift at consumers; or independent designs
on unseen features if the review treatment appears promising. Do not attribute a new rule's
knowledge benefit to better retrieval. Freeze any next protocol separately before dispatch.
Do not add mandatory production harness steps based on this pilot alone.
