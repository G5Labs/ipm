# Ontology-only review inventory: two repetitions on three features

2026-09-29. User-requested execution amendment to the earlier two-arm proposal:
**one supplied-context condition, three features, two fresh Sol repetitions each**.
No comparison arm, implementation, code review, repair or runtime test is run.

## Inputs and scope

| Feature | Original ontology input and change | Qualification |
|---|---|---|
| Failed workflow retry | Balance-study D2 H initial ontology draft on `1738018` | Includes bootstrap retry. This actual draft was not adopted by the later narrower coding experiment; do not claim this is its missing original approved diff. |
| Host deletion by draining | Initial reviewed host-drain ontology diff on worker baseline `956c61a` | Preserve ordinary Stop, explicit force, custody and provider-completion distinctions in the supplied contracts. |
| Stale editor Save | Initial stale-Save ontology diff on `12676ae` | One changed commitment; relevant unchanged identity, authority, recovery and design rules remain available. |

`prepare.py` applies the original retained patch to its original ontology snapshot.
It removes all metadata footers uniformly from old/new ontology and regenerates a
contract-only diff; governing bodies are unchanged. This prevents old implementation
assessments/source locations from becoming answers. Original patch/design hashes and
per-file input hashes are preserved in `private/manifest.json`.

Each packet contains the request, changed IDs/diff, original design's explicit governing
IDs/heading links, common design/invariant/coding entry points, and the full ontology.
The first section is `Ontology changes and governance`. The design prose and its
acceptance checklist are withheld to test inference from ontology, rather than copying
the prose plan. Governing entry points are mechanically selected from original design
references; no new evaluator-selected issue list is supplied. There is no old I1–I8,
G1–G8, bug list, source code, implementation explanation or peer report in a packet.

Packets are identical within each pair, in separate directories without Git history.
Isolation is instructional, not an operating-system sandbox; global tool/skill descriptions
remain an ambient limitation. Workers may read only packet files and write artifacts.

## Procedure

1. A fresh Astra constructs a reference inventory from these inputs alone, without old
   study findings. The parent checks source applicability and freezes it before Sol
   dispatch. Preserve original proposals and any corrections; ambiguous requirements
   remain separate. The parent knows earlier outcomes, a disclosed nonblind limitation.
2. Six fresh GPT-6 Sol/xhigh contexts receive the identical inventory task and five-minute
   allowance from first tool use. No inherited conversation, specialization, peer contact,
   additional agents or supervisor hints. First wave: retry1/host1/save1; second wave:
   save2/host2/retry2. Save partial work if time expires; no selective retry.
3. Workers infer obligations, cite governing IDs, give allowed/forbidden cases and the
   owner/boundary to inspect, and state uncertainty. No target number of rows is specified.
4. Fresh Astra evaluation checks each pair against the frozen reference and actual packet.
   Judge semantic obligations, not matching wording/headings or ID presence. Parent audits
   disputed classifications against the same inputs. Preserve independent and reconciled
   outcomes. New valid obligations and reference mistakes are recorded separately and
   applied uniformly; they do not silently change the frozen denominator.

## Measures and interpretation

For each reference obligation: covered, partial, omitted, contradicted or ambiguous.
Full coverage must retain its specified material conditions; a correct general slogan
cannot hide a wrong exception. Report per-obligation evidence and per-run counts. Count
unsupported additions/restrictions and their materiality separately.

Repeatability means both/one/neither repetitions retain each material obligation, with
their disagreements visible. Also report their union and common misses; no majority vote
or repeatability percentage is a population reliability estimate. Grouping differences
alone are not errors. The historical eight retry categories may be used only afterward
as an explanatory crosswalk, acknowledging the different bootstrap scope.

Capture public actions, output hashes, input preservation, elapsed time and actual token
receipts where available. Separate six-worker effort from Astra preparation/evaluation.
No dollar-price inference. The cap is 30 summed worker minutes; report overruns honestly.

This experiment measures deriving a review inventory given supplied governing context.
It does not measure planner production of that context, benefit versus no handoff,
correct code inspection, effective repairs, or full autonomous delivery.
