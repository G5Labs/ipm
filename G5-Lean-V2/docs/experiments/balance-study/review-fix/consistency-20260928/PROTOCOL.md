## Change requested by the user

Focused review uses three parallel Sol subagents; the main Astra agent consolidates findings.
Apply that same consolidation to general teams to isolate the allocation of attention.
The main agent knows historical defects: it may group and check new claims but MUST NOT add
historical answers to the packet or discard claims based on hidden evaluation. Preserve all
raw IDs and unresolved/rejected claims. Report this unavoidable lack of blinding. Independent
verification is separate from worker-produced evidence and never sent as repair feedback.

## Discovery

Six teams in frozen order G1, F1, F2, G2, G3, F3. Each has three fresh Sol/xhigh subagents
with no inherited conversation, working concurrently. G repeats the same full review;
F prioritizes intent/invariants, behavior/compatibility, architecture/code quality. Full
source, original PLAN, corrected sanitized ontology, revised skill and generic rubric match.
This tests specialization with a shared rubric, not old-vs-new skills or the rubric's benefit.

10 minutes per reviewer including report and checks, starting its first tool action.
The first tool initializes the timer. Incremental reports and immutable checkpoints preserve
work at the limit; main interrupts overdue sessions. Scheduling/tool interruption can cause
overshoot: retain and disclose it, no selective extensions. Consolidation allowance 5 minutes
per team, measured separately as Astra effort rather than fictional Sol consolidator time.
Source/governing meaning read-only. Private tests allowed. Reviewers cannot see peer reports.
Raw report union and consolidated claims are evaluated separately; no majority vote.

## Repair

Combine all six new consolidated reports, preserving every raw claim and disposition, into
one byte-identical packet. No historical/evaluator findings enter it. Three fresh Sol fixers
validate/save dispositions before editing, then one coherent pass up to30 minutes. Preserve
P1. Evaluate independently against original intent and unchanged/adapted frozen probes.
Then at most two 15-minute corrections per trajectory, each triggered by a fresh general
review (10 minutes total: independent findings first, then pending-ledger check). Final
fresh review after last correction. No evaluator feedback enters the loop. Stop when no
material actionable finding remains, supplied issues have evidence-backed dispositions and
available required checks have no unresolved failure. Preserve false-clean stops as stops.

## Evidence and costs

Separate retrieval, diagnosis, consolidation, attempted repair, actual repair, and uncertainty.
Seven known diagnostic outcomes plus all material original plan/governing obligations matter;
new supported findings remain eligible. Track unique causal defects, false restrictions,
raw-claim preservation, actual tokens/time, phase costs, additional loop benefit and regression.
End the report with changed-plan and governing-ontology alignment separately. No approved
ontology diff existed for this retry feature: never substitute the broader unapproved draft.
Supported/Partial/Violated/Unverified are evidence labels, not an averaged grade.

Evaluation reuses preserved baseline observations, existing 13 compatible API/DB/dispatch
checks (12 original outcomes plus allowed successful-command reuse), component recovery and
source tracing into allocation ownership, parent visibility and subset progress. New candidate
checks are necessary verification, not rerunning old experiments. Any adaptive probe is
separately named, frozen before its candidate executions and applied comparably. No real
provider/guest/browser or exhaustive concurrent-cap guarantee is claimed.

Private repos have no inherited Git history/remotes. Private services/build/tmp/dependencies,
max2 Cargo jobs and1 test thread. Only three workers active at a time; no selective competing
Astra heavy tests during discovery. Host load is sampled, actual time includes waits. Input
and evidence hashes, public action histories and token receipts exclude private reasoning.
Directory/instruction isolation is not a filesystem sandbox; audit visible access limitations.
