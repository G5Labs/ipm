# V9 MVP scope and review reconciliation

Revised 2026-09-18 in the `G5-Lean-v9` worktree. The latest user instruction makes the MVP the backend refactor and simplification. It supersedes the meeting's proposed dedicated review/explainer returned-results product and the intermediate review remedies that depended on that product. The follow-up verification was written by another reviewing agent, not by the user.

The current specification is [design v9](lean-backend-design-v9.md), its four companions and the [implementation plan](lean-implementation-plan-v9.md). Earlier versions and both original review documents are preserved. The [125-finding response](lean-backend-design-v9-review-response.md) and [data-model response](lean-backend-design-v9-datamodel-review-response.md) now give current item-level dispositions. The [verification audit](lean-backend-design-v9-review-verification-audit.md) remains a dated record of the earlier gaps; this document records how its conclusions were addressed or deferred.

## Scope removed

The MVP adds no dedicated reviewer/explainer request, acceptance or automatic child workflow; source-versioned returned-result/reply tables, APIs, UI or `g5d pr result`; designated producer or attempt candidate; publication-dependent task completion/hold; special review-child idle policy; result-triggered stop/cleanup or shipped result-submission skill. P4.14 is withdrawn, its identifier reserved and all dependencies removed. No replacement delivery milestone or dormant schema is introduced. A future product proposal must scope these semantics together.

Ordinary checked forks, parent/source linkage, exact shared branch naming, owner-only runtime/write access, Git-only reader browsing, shared agent conversations/output/artifacts, native provider questions, optional jobs and dependencies across continuations remain. Existing document/ontology projections and ordinary review/explainer prompts remain. Finishing an agent turn follows ordinary task completion; workspace compute follows ordinary stop/idle/lifecycle rules.

## Subsequent fork-reservation simplification

The user subsequently approved dropping `workspace_fork_reservations` from MVP. `workspace_forks` in `pending` or `aborting` is now the sole durable name-claim owner, as specified in design §§5.1/5.8 and the P4.1/P4.5 prompts. Frozen member IDs plus the exact proposed name identify the claim; a short repository-row-locked READ COMMITTED transaction performs a fresh all-tenant-claims query before insertion. Prefix conflicts, private claims, repository deletion/import/bootstrap, crash recovery, terminal settlement and late-writer fencing are explicit implementation/test obligations. This removes a table and its synchronization/FK backstop, not the reservation mechanism or atomic Git proof refs. No expiry frees unfinished work. The original reviews and earlier versions remain historical; current responses distinguish this decision from the separate proof-ref question.

## Validation boundary

This revision changes Markdown only. Document checks cover current contract links/fences, removed-scope references, matching plan/tracker/prompt dependencies, an acyclic graph and dependency-safe three-person schedule, all125 response headings, preserved merged tracker rows, unchanged source reviews and earlier versions, and whitespace. Those checks establish document consistency, not runtime security or user-visible correctness.

Implementation prompts distinguish dependency-local fixtures from later composition. Newly named routes, scripts and tests are implementation targets. Exact pinned-provider behavior, Git/VM/browser fault tests, measured budgets, both required CI lanes and authorized QA observations remain work for the owning implementation PRs. No application code, migration, deployment or PR is included in this revision.
