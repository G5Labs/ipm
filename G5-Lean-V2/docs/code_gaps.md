# Code issues and simpler design options

These are open findings from the ontology audit, unless marked otherwise. Each row
says what can go wrong and how the audit found it. **None of the reported failures
was reproduced by running the application.** Code inspection and finite TLA+/TLC
models support the findings; a passing model of a repair does not mean that repair
has been implemented.

The intended behavior comes from [Ben's source](ben_new_ontology.md) and the
[ontology](../.g5/ontology/root.g5.md). [Coverage](../.g5/uplift/ben-ontology/coverage.md)
records which parts were examined. Proof files remain in the linked historical
commits, outside this PR. This final edit improves the report; it does not rerun TLC,
fix application code or settle the policy questions below.

## Open bugs and missing behavior

“Code + model” means the audit followed the real code and found a corresponding
failure in a bounded model. “Inspection” means the finding comes from source,
configuration or history without a model of that failure. The evidence links retain
source locations, assumptions and proposed reproductions.

### Workspace, Git and files

| Issue | What goes wrong | How it was found |
| --- | --- | --- |
| **WORKSPACE-CASCADE — child deletion is missing** | Deleting a workspace with live children is refused. The intended operation deletes the descendants too, with extra confirmation for non-review children owned by someone else. Stopping the parent does not provide that behavior. | **Code + model:** [deletion service and WorkspaceProducts](../.g5/uplift/ben-ontology/investigations/workspace.md), `DeleteSupported` counterexample. |
| **WORKSPACE-REVIEW-MERGE — a review copy cannot merge** | The review-copy rules allow an optional merge, but mutation policy and the merge route reject it. | **Code + model:** [review policy and merge route](../.g5/uplift/ben-ontology/investigations/workspace.md), `ReviewMergeSupported` counterexample. |
| **WORKSPACE-REVIEW-SETTLEMENT — applied work can still be rejected** | Accept writes and checkpoints the file before recording acceptance in SQL. A crash between those steps leaves the changed file with an open suggestion; a later Reject or Withdraw can describe it as unapplied. Ordinary checkpoint errors are already handled. | **Code + model:** [acceptance investigation](../.g5/uplift/ben-ontology/refinement/workspace-gaps.md#workspace-review-settlement--applied-review-can-remain-rejectable-after-transaction-failure). ReviewAcceptance fails `NoFalseRejection` after the file change and before SQL commit. |
| **WORKSPACE-SAVE-BLOB — Save can publish different bytes** | Save stages a file, then validates a later hash. A native process can change A→B→A around those steps: Git stages B, while the reply identifies A. The private index lock does not tie the two observations together. | **Code + model:** [selected Save investigation](../.g5/uplift/ben-ontology/investigations/workspace.md), SelectedSave fails `ExactSavedBlob`. |
| **Shared file-write race — an intervening edit can be lost** | A native process can edit a file after G5's last hash check but before replacement. Explicit template overwrite consent and review-discard preview checks do not exclude that writer. Related check/delete races remain. | **Code + model:** [ExplainerTemplates](https://github.com/G5Labs/G5-Lean/blob/345b546e9fed5477e6fdf3c77ad87002ed558dd6/.g5/TLA_verification/ben-quantitative/platform/README.md), `NoLostWrite`; `files.rs` checks at line 631 and renames at 634–640. This is the existing shared mutation limitation, not another independent bug per consumer. |
| **GIT-GAP-1 — a multi-repository merge can become partly visible** | After all provider PRs merge, automatic import can publish one repository while skipping an unavailable sibling. The internal update is atomic, but it contains an incomplete set of repositories. | **Code + model:** [automatic importer and ProviderImport](../.g5/uplift/ben-ontology/investigations/git.md), `NoPartialWorkspaceMerge` fails. Explicit provider-first import handles these member failures; the alternate automatic writer does not. |
| **GIT-GAP-3 — no public repository-removal operation** | Organizations can add repositories through import, but no public operation was found to remove one. Deleting storage or cleaning workspace refs is not the same feature. | **Inspection:** [registered APIs, production writers and storage primitive](../.g5/uplift/ben-ontology/investigations/git.md). A separate model checks only a proposed unused-repository removal flow. |
| **GIT-GAP-4 — backups do not establish Git recovery** | The self-hosted backup saves SQL/configuration but omits the separate Git directory. Hosted infrastructure does not establish recurring Git backups and recovery; a manual development Filestore backup is not that assurance. | **Inspection:** [backup scripts, storage layout and deployment configuration](../.g5/uplift/ben-ontology/investigations/git.md). BackupBoundary shows why SQL-only or uncoordinated SQL/Git copies can be inconsistent. Customer backup arrangements and live restores were not checked. |
| **GIT-GAP-5 — read-only browsing can expose unpublished files** | A nonowner, or an owner of a stopped workspace, can receive a retained dirty snapshot when branch observations still match. The supplied rule requires committed branch content for that browsing path. | **Code + model:** [public file route and reader selection](../.g5/uplift/ben-ontology/reviews/workspace-git.md), SavedRead fails `CommittedBrowsing`. Dirty snapshots remain valid for explicitly authorized recovery/fork uses. |

### Runtime and infrastructure

| Issue | What goes wrong | How it was found |
| --- | --- | --- |
| **RUNTIME-001 — ignored files remain accessible through direct operations** | Tree enumeration applies ignore rules, but direct read, stat, list, write, delete and rename check path confinement without the same ignore policy. | **Code + model:** [FileService inspection](../.g5/uplift/ben-ontology/investigations/runtime.md), FileVisibility fails `NoIgnoredAccess`. |
| **RUNTIME-002 — an old Stop can clear a replacement VM's notices** | A delayed Stop reply cannot update the replacement VM row, but workspace-wide cleanup still runs when that guarded update changes zero rows. Notices for the new VM can be withdrawn. | **Code + model:** [release and task cleanup](../.g5/uplift/ben-ontology/investigations/runtime.md), StaleRelease fails `NoStaleSettlement`. |
| **RUNTIME-004 — preview cleanup can run before the app has stopped** | Stop logs termination failures and ignores the final process-group signal result, then allows cleanup and success. Task completion can also admit a new preview while the old process remains alive. | **Code + model:** [preview and task review](../.g5/uplift/ben-ontology/reviews/runtime-full.md), PreviewLifecycle fails both `CleanupAfterExit` and `NoOverlappingApps`. Reaping only the leader does not prove all child processes exited. |
| **RUNTIME-005 — configurable host-count limits are missing** | Managed capacity now grows with demand and retires empty hosts. The remaining gap is Ben's optional, separately configurable minimum/maximum **host count**; a VM quota or growth bound does not supply it. | **Inspection, narrowed after rebase:** [managed capacity](../backend/g5-api-core/src/services/hosts/host_capacity.rs). The earlier claim that no demand-growth component exists is superseded. This is optional configured behavior, not an always-on scaling requirement. |
| **RUNTIME-006 — cache credentials are broader than one organization** | QA grants a compute identity read access across `guest-sccache/`. Request filtering normally chooses an organization prefix, but the credential itself can reach more. | **Configuration + model:** [IAM investigation](../.g5/uplift/ben-ontology/investigations/runtime.md), CacheCredentialScope distinguishes a filtered request from restricted credentials. Live IAM and guest token access were not tested. |
| **RUNTIME-007 — cleanup can delete a newly attached cloud host** | Cleanup reads a created instance as unowned. Recovery can then attach that instance before the cloud delete, so the earlier read no longer justifies deletion. | **Code + model:** [bring-up and linkage recovery](../.g5/uplift/ben-ontology/investigations/runtime.md), CloudLinkage fails `NoOwnedCompensation`. The bring-up source was unchanged at the rebase check. |
| **RUNTIME-008 — rotation may use an outdated “empty host” observation** | A rotation statement can observe no VM, wait for placement's host-row lock, then request teardown after placement commits a VM. It does not reread VM occupancy afterward. | **Conditional code/model finding:** [rotation investigation](../.g5/uplift/ben-ontology/investigations/runtime.md), HostRotation. It depends on the stated PostgreSQL Read Committed behavior; that schedule was not run against PostgreSQL. |
| **RUNTIME-IDLE-TERMINAL — a quiet terminal does not prevent idle Stop** | An open browser terminal renews activity for Text/Binary input, but not merely for remaining open. A quiet connected terminal can therefore be stopped as idle despite the intended rule. | **Code + model:** [terminal refinement](../.g5/uplift/ben-ontology/refinement/runtime-gaps.md), TerminalIdle fails `OpenTerminalPreventsIdle`; the model also permits idle Stop after disconnect. |
| **RUNTIME-EVENT-DELETE — deletion can leave an event retrying forever** | Workspace deletion clears the API event history after Stop replies, before the host's final event is acknowledged. If event 3 arrives alone afterward, the acknowledgment query returns 2; reconnect keeps replaying 3 without progress. | **Code + model:** [event-deletion investigation](../.g5/uplift/ben-ontology/quantitative-refinement/runtime.md#event-deletion-investigation), HostEvents. The trace preserves ordered transport. It demonstrates stuck retention, not replacement-state corruption or loss of a new workspace's data. |
| **RUNTIME-EXIT-FACT — a stopped VM can lose its exit record** | Stop/status/exit-monitor paths remove the active VM entry, then ignore a failed Exited journal write. A failure before file replacement restores the old journal; no remaining active entry retries that exit, and restart loses its payload. | **Code + model:** [terminal-event investigation](../.g5/uplift/ben-ontology/quantitative-refinement/runtime.md#terminal-producer-gap-runtime-exit-fact), TerminalFact fails `SuccessfulStopRecoverable`. Physical Stop may still be truthful; the missing guarantee is durable exit evidence. No filesystem-fault test was run. |

### Identity, chat and notifications

| Issue | What goes wrong | How it was found |
| --- | --- | --- |
| **CI-KEYED-FORK — a retried history fork can create another chat** | The ordinary, non-persona history-fork API accepts a request key but does not use the request-claim mechanism. Repeating the same keyed request can create another session. | **Code + model:** [keyed-fork investigation](../.g5/uplift/ben-ontology/quantitative-refinement/identity.md#ci-keyed-fork--ordinary-history-fork-ignores-accepted-request-key), KeyedCreation compares the bypass with a shared keyed transaction. |
| **CI-G1 — a revoked invitation can still grant membership** | OAuth login reads pending invitations, then uses that saved list to grant membership even if an administrator revoked one in between. Explicit invitation acceptance locks the current row; automatic acceptance does not. | **Code + model:** [invitation investigation](../.g5/uplift/ben-ontology/investigations/chat-identity.md), Invitation fails `NoRevokedGrant`. Closed by [#660](https://github.com/G5Labs/G5-Lean/issues/660): OAuth acceptance locks and conditionally claims the current row. |
| **CI-G2 — UI preferences can cross user or organization boundaries** | One browser-wide `g5-user-settings` key holds preferences that should belong to a particular user and organization. A switch can reuse another scope's preferences. This is not a finding about API-secret storage. | **Code + model:** [settings investigation](../.g5/uplift/ben-ontology/investigations/chat-identity.md), UiPreferenceScope and PreferenceRepair cover key scope, delayed events and stale callbacks. |
| **CI-G3 — added permissions can exceed the viewer role** | Explicit, organization or workspace grants can raise a viewer above read-only, including `org:admin`. The older additive design explains the behavior but conflicts with Ben's later viewer ceiling. | **Code, history + model:** [permission investigation](../.g5/uplift/ben-ontology/investigations/chat-identity.md), ViewerCeiling/ViewerRepair. No cross-organization or VM-owner bypass is claimed; discussion/voting exceptions remain undecided. Closed for the viewer role by [#660](https://github.com/G5Labs/G5-Lean/issues/660) (`g5.organization.viewer-ceiling`). |
| **CI-G4 — notification preferences are missing** | Ben calls for notification settings, but the supported settings/delivery components provide no delivery-preference control. The removed development-only form never had backend storage; a private inbox and read state do not replace preferences. | **Inspection + history:** [settings and notification review](../.g5/uplift/ben-ontology/reviews/identity-full.md). NotificationPreference compares a possible design only; channels, categories and timing still need a product decision. Former ID: CI-Q2. Partly closed by [#991](https://github.com/G5Labs/G5-Lean/issues/991): the first real server-side delivery preference (`users.email_on_approval_request`, account-wide, default on) now gates the approval-request and approval-decision emails (`g5.user.notifications`); the general channels/categories/timing framework stays open. |
| **CI-LAUNCH-CONFIRMATION — queued work can use choices the user did not confirm** | Enqueue checked the visible model/account choices, but the queue kept only preferences. Changed inherited defaults could alter the first attempt. | **Code + model:** [queued-launch investigation](../.g5/uplift/ben-ontology/refinement/identity-gaps.md#ci-launch-confirmation--confirmed-choices-are-lost-between-enqueue-and-attempt-admission), QueuedLaunchAgreement failed `ExecutionHonorsConfirmation`. Addressed by [#629](../.g5/pr_ontology_diff_design/issue-629/ontology-plan.md): inputs retain confirmation and first dispatch revalidates it; admitted retries retain their choices. Current credentials are still required. |
| **SEC-WS-ORG-ADMISSION — a removed member can open a new organization stream** | An unexpired ticket can authorize a new organization WebSocket subscription after membership removal. The issue is new admission, not whether an existing stream must close immediately. | **Code + model:** [subscription investigation](https://github.com/G5Labs/G5-Lean/blob/072a12d3e99032ee3a7356837542c5edeb825984/.g5/TLA_verification/ben-coverage/platform/README.md#sec-ws-org-admission), `CurrentOrgAdmission` fails. No live exploit was reproduced. |
| **PLATFORM-REPORT-CLAIM — two workers can create the same bug report** | After a delivery claim expires, a stale worker and its replacement can both observe that external creation has not started. The later update checks only the row ID, not current attempt ownership or whether the row was deleted, before POST. | **Code + model:** [report-delivery review](../.g5/uplift/ben-ontology/reviews/workspace-git-full.md), ReportDelivery/ReportClaim expose duplicate creation and stale writes. |

## Conditional findings and policy choices

These must not be presented as confirmed production bugs. The ontology's questions
keep provisional choices visible until the original authority or a new decision
settles them.

| ID / topic | What remains uncertain | Evidence and current working rule |
| --- | --- | --- |
| **CI-KEY-DELETION-CONDITIONAL** | Physically deleting a keyed chat result cascades deletion of its request row. A still-admissible retry would lose its original-result/refusal record. | [Schema and KeyedCreation](../.g5/uplift/ben-ontology/quantitative-refinement/identity.md#ci-key-deletion-conditional--key-fence-follows-deleted-child-by-cascade). No standalone production deletion route was found; normal workspace deletion is soft and separately blocks admission. Account/organization erasure needs its own retention policy. |
| **WORKSPACE-REVIEW-VERDICT-POLICY** | May a listed reviewer's Approve verdict create formal approval without an addressed pending request, and how can it be withdrawn? | [ReviewVerdictSync and authority history](../.g5/uplift/ben-ontology/quantitative-refinement/workspace.md). Provisionally require an eligible addressed request or direct-owner authority; review publication and earlier phase decisions survive later sync failure. |
| **RUNTIME-003 — request isolation** | The supplied rule says each dispatcher API request forks a process; filesystem RPCs currently use blocking threads. Is that stronger isolation required for every request? | [Structural inspection](../.g5/uplift/ben-ontology/investigations/runtime.md), not an OS-isolation proof. Preserve the per-request rule until the exception is decided. |
| **RUNTIME-Q-PHYSICAL — one physical VM** | Database ownership prevents conflicting logical authority, but does not prove a partitioned VM has died. Host-enforced expiry termination is deferred. | [Physical uniqueness question](../.g5/ontology/software_architecture/workspace_vm.g5.md#g5.vm.physical-uniqueness-question). | **RUNTIME-Q-LOCAL — process mode** | An explicitly acknowledged local process mode exists; its selector does not establish that deployment is network-local. | [Local-mode question](../.g5/ontology/software_architecture/hosts.g5.md#g5.runtime.local-mode-scope). Keep production microVM-only until the development exception is scoped. |
| **CI-Q1 — existing-user invitations** | Existing users are added immediately on invitation, while Ben describes joining at login. | [Invitation question](../.g5/ontology/features/organizations.g5.md#g5.organization.existing-user-invitation-question). Provisionally grant at verified login; an immediate-add exception needs a decision. |
| **GIT-Q-BASE — Base creates a remote branch** | Earlier human intent permits confirmed Make Remote from Base; Ben's later rule says Base never pushes. | [Base question](../.g5/ontology/software_architecture/git.g5.md#g5.git.base-create-exception). Preserve the no-push rule pending reconciliation. |
| **CI-Q-COLLABORATION — viewer participation** | Reply, advisory-vote and reader-suggestion routes use read permission. It is unclear whether those are intended exceptions to the viewer ceiling. | [Viewer question](../.g5/ontology/features/organizations.g5.md#g5.organization.viewer-collaboration-question). Keep role eligibility required; finite action models do not settle the policy. |
| **Returning-member admission** | Code allows invited people and existing members past the first-admission email allowlist, but the original policy decision was not recovered. | [Admission question](../.g5/ontology/features/users.g5.md#g5.user.admission-continuity-question). Provisionally retain those exceptions with verified identity; AdmissionContinuity compares policy options rather than proving one is intended. |
| **Spend limits and granular grants** | Exposed spending settings conflict with earlier deferral; older plans to retire granular grants conflict with active users of them. | [Remaining questions](../.g5/uplift/ben-ontology/clarifications.md). Keep accounting and supported grants within current role limits; do not claim a working spend cap or unrestricted grant union. |

## Simpler architecture that keeps the same requirements

The common opportunity is to put each decision in one existing component and make
all callers use it. The table names concrete changes, the behavior they must preserve,
and the checks still needed. These are repair/design candidates, not shipped changes
or a claim that the model has found the smallest possible architecture.

| Area / issues | Concrete simplification | What it preserves; evidence and next check |
| --- | --- | --- |
| **One request-claim path for keyed chat creation** — CI-KEYED-FORK | Reuse the request claim and transaction for every keyed start/history-fork. Resolve persona instructions and history only after the claim succeeds. Keep ordinary history forks session-only: sharing the claim must not enqueue a new input or task. | KeyedCreation retains the original result across retry, rejects a changed payload and permits recovery after rollback/lost reply. No second deduplication service is needed. Test the ordinary-fork route with simultaneous equal requests and a dropped response; decide deletion retention separately. |
| **One invitation transaction** — CI-G1 | Inside the OAuth membership transaction, lock or conditionally claim an invitation that is still pending, unexpired and backed by the verified identity and required proof. Grant membership and consume the invitation together; revoke, decline and explicit acceptance use the same row. | InvitationRepair allows normal and repeated logins while refusing revoked/unbacked grants. An extra invitation ledger still needs this guard. Force revoke-before-claim, expiry, duplicate login and rollback schedules in PostgreSQL. |
| **Keep workspace-owner eligibility in the existing database constraint** | Keep the service's early membership check for helpful errors and the eligible-owner foreign key for the final database guarantee. Refuse membership removal/viewer demotion while workspaces remain; transfer or delete them explicitly instead of choosing a replacement owner automatically. | OwnerMembership shows why the early check alone can race, while the existing constraint preserves eligibility and allows transfer-then-removal. No second ownership ledger is needed. Test real foreign-key/row-lock contention and the separate VM termination requirement during transfer. |
| **One current-role permissions calculation** — CI-G3, SEC-WS-ORG-ADMISSION | Apply the viewer ceiling after all grants in both shared permission resolvers; keep authority valid through mutation commit. Use current membership when admitting a new organization stream. | ViewerRepair rejects route-only checks, stale caches and unlocked admission; the subscription model denies removed members while allowing current ones. Reuse membership state rather than another permission cache or ticket ledger. Test demotion racing a write, retained grants and new subscriptions after removal; decide existing-stream revocation separately. |
| **One preferences owner, scoped to user and organization** — CI-G2, CI-G4 | Key settings by `(user, organization)` and keep callbacks/events tied to that captured scope. Reset or load before displaying a new scope; use defaults for ownerless legacy browser data. Add real notification preferences here once their meaning is agreed. | PreferenceRepair shows a second durable update/ack mechanism does not fix stale callbacks. A conditional NotificationPreference comparison needs no extra outbox for best-effort in-app delivery and keeps the private inbox. Test switches, delayed events, reload and preference/read failure; cross-device settings and guaranteed email/push delivery are additional requirements. |
| **Keep launch confirmation with the queued request** — CI-LAUNCH-CONFIRMATION | Store the optional confirmed model/account choices with the existing inbox/task. Compare them with current authorized choices before creating the first immutable attempt; changed choices require fresh review. | QueuedLaunchAgreement permits fresh-review recovery and live defaults when no confirmation was supplied. It does not reuse obsolete credentials or need another configuration store. Queue behind capacity, change defaults, then verify first-attempt refusal/review. |
| **One file-mutation boundary; one captured Save version** — shared file race, WORKSPACE-SAVE-BLOB | Put preview/version checks and the actual file change in the shared mutation component. For selected Save, capture bytes once, validate that capture, stage from it and verify the resulting Git blob. Reuse private-index isolation and reference compare-and-swap. | SelectedSave rejects independent stage/hash observations; ReviewDiscard and ExplainerTemplates preserve selected-only edits, explicit overwrite choice and honest partial results under their stated assumptions. A lock used only by RPC callers cannot exclude native processes. Test A→B→A, a native edit between check and rename/delete, clean filters, unrelated staged files and failed publication. |
| **Separate applying a suggestion from publishing it** — WORKSPACE-REVIEW-SETTLEMENT | Keep recovery with the existing suggestion record and selected-Save operation. After a crash, establish whether the change was applied before allowing Reject/Withdraw or another application. Keep publication pending without reversing acceptance. | ReviewAcceptance checks no false rejection and recovery without applying twice. SQL locking alone cannot undo file changes. Choose a durable application record or reliable file reconciliation, then inject failures after write, checkpoint and before SQL commit; include ambiguous source changes and native writers. |
| **One review-round writer and one approval decision API** — WORKSPACE-REVIEW-VERDICT-POLICY | Keep rounds, carried decisions and discussion in the existing review service. Route any authorized formal-approval sync through the same request/owner checks as other decisions; commit each phase separately. | ReviewRounds preserves decisions only for the same proposal/content; ReviewVerdictSync preserves publication and earlier phase decisions if a later phase fails. This avoids a second approval state machine. Requestless reviewer authority and withdrawal remain policy decisions; test changed proposals, partial failure and retry. |
| **Use existing PR operations for review merge** — WORKSPACE-REVIEW-MERGE | Let the reviewer create a PR aimed at the parent, then let its current owner or an authorized Base administrator merge it through normal version, approval and repository checks. Keep unrelated review-copy mutation restrictions. | ReviewMergeReuse checks the actor, parent target, fixed commit set and successful handoff. Merely removing all review guards grants too much. Test the actual reviewer-to-owner/admin flow and provider publication. |
| **Delete a checked descendant tree** — WORKSPACE-CASCADE | Collect descendants and required confirmation for other owners' non-review children. Stop their VMs through existing runtime operations. Before marking the tree deleted, recheck its complete membership, confirmation, stopped VM instances and unfinished fork/merge blockers under the shared workspace, repository and VM locks. Retry reference cleanup from retained identities. | CascadeRepair checks changes to the tree and confirmation during deletion. Every child creator and ownership writer must share the locking rule. Test a child added mid-delete, changed ownership, failed Stop, restart and repeated cleanup. |
| **One complete repository set for accepted merges** — GIT-GAP-1 | Derive the automatic-import hold from the PR's durable, admitted set of repository commits before provider effects. Keep it until the whole internal merge completes or recovery establishes that no merge was accepted. | AcceptedImportRepair retains uncertain attempts and completes after lost acknowledgments without showing a partial merge. Reuse the existing importer/recovery path rather than another queue. Test all automatic-import callers with one unavailable sibling and concurrent head/member changes. |
| **Keep public browsing and dirty recovery separate** — GIT-GAP-5 | Use the published-snapshot reader for nonowners and stopped-workspace browsing. Reserve saved dirty snapshots for explicit restore/fork operations that validate their saved receipt. | SavedRead distinguishes those uses without a new snapshot store. Test every public reader, stopped/failed states and permitted nonowner durable forks; fresh live capture still requires the owner. |
| **Extend the repository catalog and backup command** — GIT-GAP-3, GIT-GAP-4 | Add removal through the catalog, initially refusing the required docs repository or any referenced repository; recheck dependencies under the writers' lock. Extend backup to stop/drain writers and save SQL, configuration and Git as one checked bundle; restore offline before reopening. | RepositoryRemoval covers only unused repositories. BackupBoundary covers required-reference consistency, not actual filesystem/storage reliability. In-use removal needs a separate decision. Test new dependencies racing deletion and a real restore after interrupted backup; hosted scheduling, retention and recovery targets remain operational work. |
| **One incarnation-checked completion transaction** — RUNTIME-002 | Run notice/task cleanup only when the VM row transition actually matches the expected instance. Keep that transition and dependent SQL changes in the same transaction. | StaleRelease rejects a late old Stop while allowing a valid current Stop. No new completion ledger is needed. Test replacement between request and response, then check failed-start and loss callers use the same rule. |
| **Keep host-event history until replay is safe** — RUNTIME-EVENT-DELETE | Preserve the existing per-VM event history through workspace deletion until outstanding host events are acknowledged. Let the event component determine when it can be pruned. | HostEvents drains under the retained-history comparison and stalls when deletion removes the prefix. A different acknowledgment formula cannot reconstruct deleted events. Specify eventual cleanup, then test Stop/reply/event ordering, disconnect and restart with a late final event. |
| **Keep failed terminal recording recoverable** — RUNTIME-EXIT-FACT | Before a commanded Stop, persist pending reconciliation in the existing lifecycle/journal component. Retry a failed terminal write while its receipt is available; distinguish physical Stop from durable recording and delay successful recording acknowledgment until persistence. | TerminalFact checks the pre-stop obligation, in-process retry and replay of a persisted event. After restart it retains only an unfinished obligation if the payload was lost; it does not invent the exit result. Exact receipt recovery and spontaneous exits still need design and filesystem-fault tests before this is a complete repair. |
| **Do not release preview ownership before confirmed exit** — RUNTIME-004 | Keep the existing “closing” state until the entire application group has stopped and cleanup finishes. An uncertain Stop remains blocked; task failure must not reopen preview admission. | PreviewLifecycle prevents premature cleanup and overlapping apps while allowing normal restart. Test failed signals, deadlines, leader exit with live children and supervisor loss; reuse confirmed workspace Stop/VM-loss handling where valid. |
| **Derive idle activity and capacity from existing state** — RUNTIME-IDLE-TERMINAL, RUNTIME-005 | Renew activity from a verified-live authorized terminal connection and stop renewing on disconnect. Add the optional host-count bounds to the existing managed-capacity service rather than a second scaler. | TerminalIdle permits quiet-terminal activity and later idle Stop; choose renewal within the minimum idle interval and keep owner/instance checks. Autoscale limits are **not modeled**: decide how manual hosts, replacement overlap and uncertain deletion count, then test competing ticks and capacity recovery. Guest output or unused preview keepalives must not create activity. |
| **Use existing host lifecycle locks for safe retirement** — RUNTIME-007, RUNTIME-008 | Keep live unlinked instances for recovery; delete only when authoritative terminal/absent state excludes later attachment. For rotation, acquire placement's host lock, read VM occupancy in a new statement, then mark draining before commit. | CloudLinkage shows why an extra deletion flag is insufficient; HostRotation rejects repeating the stale predicate inside the same waiting statement. Test real PostgreSQL interleavings, all attachment/forced-retirement callers, multiple cloud results and failed-delete retry. |
| **Restrict the shared file API and the actual cache credential** — RUNTIME-001, RUNTIME-006 | Apply one current-checkout ignore policy to every file entry point, both rename paths and watch admission. Issue cache credentials restricted to one organization's read prefix, with no write permission. | FileVisibility and CacheCredentialScope show why tree-only filtering and facade-only credential scoping are insufficient. Test ignore negation/ancestor changes, tracked-file rules and all entry points; verify live IAM, rotation/revocation and sibling-prefix denial. A restricted token cannot help if a broader metadata credential is still reachable. |
| **One current claim for bug-report delivery** — PLATFORM-REPORT-CLAIM | Atomically reserve external creation only if it has never been reserved, using the current attempt/status and checking affected rows. Reclaiming delivery must not authorize a second POST. Require current ownership on every delivery-state write and retain uncertain-result reconciliation. | ReportClaim rejects stale/reclaimed/deleted-row writers.
