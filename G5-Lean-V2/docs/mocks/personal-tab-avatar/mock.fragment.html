Personal workspace tab avatar

Today a personal workspace tab has an empty glyph slot: the strip only knows phase icons, and a personal workspace is not in the organization's workspace list. The proposal fills the slot with the owner's avatar.

Glyph detail (2×)

Design notes

What changes

  • A tab whose route is a personal workspace (/:org/me or /:org/users/:handle) shows the owner's round avatar where other tabs show the phase icon. Nothing else on the tab moves: label, close button, drag and keyboard order are unchanged.
  • The avatar is the person's OAuth picture (avatarUrl); without one it is the deterministic initial-and-tint fallback already used by IdentityAvatar on Home and in provenance panels, so the same person has the same tint everywhere.
  • The signed-in person's own tab reads useAuth().user, which the strip already has; another member's tab reads the resolved personal workspace's owner from the organization roster.
  • The glyph is decorative: the tab's accessible name stays the label, and the avatar's tooltip is the owner's display name.
  • Ordinary workspace tabs keep their phase icons, and a tab for a workspace the list lacks keeps its empty slot, as g5.workbench.tabs states.

Assumptions to confirm

  • Size: 14 px (the phase icon's 13 px box plus 1) keeps the strip's rhythm; 16 px reads better as a face but is visibly bolder than the phase icons. Default in this mock: 14 px.
  • Other members' personal tabs also show that member's avatar (shown here for users/ben-vandiver). Alternative: only the caller's own tab.
  • Label stays "Personal workspace" for the caller and users/<handle> for others; this change does not touch it.
  • Home side panel and Home's compact personal panel are unchanged; only the tab strip gains the avatar.
  • No status ring or VM indicator on the avatar; the strip shows none for other tabs either.
