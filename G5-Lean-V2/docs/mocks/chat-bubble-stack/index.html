Chat bubble stack

Every ongoing chat of the workspace gets its own round bubble above the bottom-right Chat corner button. The bubble's face shows what the chat is doing: working, waiting for your answer (a question or an approval), or idle (waiting for your next command). The style is a user setting: Off (today's button only), Still, Animated, or 3D; the stack layout is a second setting (column by default). Hover a bubble to see its label; click it to open that chat in the floating panel.

"Still" is the common opposite of "Animated" in image settings (still image vs animated image); "3D" is a style, not a motion level, so it stays its own value. Animated and 3D obey the browser's reduced-motion preference by falling back to Still.

What a bubble is

  • One bubble per ongoing chat session of this workspace, from the session list the page already polls (GET /workspaces/:id/sessions, activity). A session is ongoing while a turn runs (activity.activeTurnStartedAt), while it waits for your answer, and while its last result is unseen (activity.unseenResult). An idle chat whose result you have seen has no bubble (to confirm, see questions).
  • Faces: working = gears, waiting for your answer = question mark (an AskUserQuestion or a permission/approval prompt), idle = sleeping (turn finished, waiting for your next command). Rings: working blue, waiting amber (pulsing), idle none. The dot marks an unseen result.
  • Order, bottom to top (nearest the button first): waiting for your answer, working, idle; within a group, most recent activity first.
  • Click opens that chat in the floating panel at the right edge, exactly like the Chat button but with that session active. Hover (or focus) shows the chat title and state. The whole corner moves together when you drag the Chat button.
  • Hidden with the Chat button: mobile, Chat in the center, panel open, modal overlay. In Off, nothing changes.

Styles and assets

  • Still uses gears B, question B and sleeping frame 1, scaled to 96/192 px (1x/2x). Animated alternates gears A/B (0.55 s per frame), question A/B (0.7 s) and sleeping 1/2 (1.2 s).
  • 3D draws a robot-heads head (npm i robot-heads, MIT, React 18+, 2D canvas, no runtime deps, ~94 kB unpacked) with state working / happy / sleeping, size 40, interactive off, antenna on, floorShadow off. The TV head is the library's default; the round head fits the circle better.
  • Under prefers-reduced-motion Animated and 3D render as Still (3D with paused).
  • Images ship in the frontend bundle (frontend/public/ or imported assets); nothing is fetched from the robot-heads site at run time.

Data today and what is missing

  • "Working" and "idle with unseen result" come from the existing session activity (also used by the picker's spinner/dot, ChatActivityIndicator). The list refreshes every 15 s while a turn runs and on chat.activity WebSocket events.
  • "Waiting for your answer" is only known for the open session today (pending AskUserQuestion / approval in its timeline). The closest list-level signal is the task status waiting (activity/current), which does not separate a question from a permission prompt. The plan would add a per-session flag (for example activity.awaitingInput) on the server so every bubble can show the question face.

Decisions (2026-10-29) and what is left

  • Decided: "waiting for a question" includes permission/approval prompts; sleeping animates between the two supplied frames; the 3D question face is happy; the stack layout is a second setting, default column; both settings live with the other appearance settings (per browser, g5-user-settings).
  • Open: when does a sleeping bubble leave the stack? Mocked: it stays while the chat's last result is unseen and goes once you open that chat. The alternative, a bubble for every chat that waits for a command, would list every session of the workspace.
  • Open: option names, Off / Still / Animated / 3D (mocked) versus None / Static / Animated / 3D.
  • Open: a cap on the column (for example 5 bubbles and "+N")?
