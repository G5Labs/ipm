Outgoing bank transfers

Customers can see when a cancellation is in progress while the bank waits for the payment network.

Example baseline 8a42c1d 2 added 1 modified Illustrative evidence · Select a tag to see details

Sending money

  • When a customer sends money to another bank, the transfer starts as Pending and the bank reserves the amount from the sender’s available balance.

    Outgoing transfer integration test

    Submitting a transfer for $50 returns Pending and lowers the available balance by $50.

    • If the available balance is too low, the bank declines the transfer and leaves the balance unchanged.

      Insufficient funds test

      Trying to send $50 with $40 available leaves the balance at $40 and creates no transfer.

Requesting cancellation

  • Only the sender can start a cancellation, and only while the transfer is Pending.

    Cancellation eligibility tests

    The bank rejects requests from other customers and attempts to start a cancellation after settlement.

  • The sender has 24 hours from sending the transfer to start a cancellation.

    Cancellation deadline test

    The sender can start a cancellation before the deadline. A first request after the deadline leaves the transfer unchanged.

  • Modified

    When the bank accepts a cancellation request, it shows Cancellation requested until the payment network confirms cancellation or settles the transfer.

    Cancellation lifecycle · State machine

    Can a requested cancellation appear final before the network decides?

    Binding
    RequestCancellation → Pending becomes Cancellation requested.
    Recorded check
    TLC · NoFinalStatusBeforeNetworkDecision held in the bounded model.
    Before

    The bank shows the result of a cancellation request when the payment network responds.

  • Added

    If the sender repeats an unresolved cancellation request, the bank returns the current status without creating a second request.

    • The rule applies even when two requests arrive at the same time.
    • The sender can repeat the request after the 24-hour deadline while it is still unresolved.

    Cancellation request handler · Verus proof

    Binding
    request_cancellation → RequestCancellation
    Proof scope
    Repeating a request preserves the original request and creates no second network job, including when two calls arrive together.
  • Added

    If the network does not reply, the bank keeps showing Cancellation requested and retries the same request while it is unresolved.

    • Each retry uses the original cancellation request ID.
    • Retries stop when the network confirms cancellation or settles the transfer.

    Network timeout integration test

    With the first reply withheld, the displayed status stays Cancellation requested and the retry uses the original request ID.

Resolving cancellation

  • When the network confirms cancellation, the bank marks the transfer Cancelled and releases the reserved money back to the sender. Both changes happen together, exactly once.

    Cancellation confirmation handler · Verus proof

    Binding
    confirm_cancellation → ConfirmCancellation
    Proof scope
    Every committed confirmation changes the status and releases the reserve together. Replaying the confirmation changes neither.

    • The bank charges no fee for a confirmed cancellation.

      Cancellation balance test

      After a $50 transfer is cancelled, the sender’s available balance rises by the full $50.

  • If the network settles the transfer before confirming cancellation, the bank marks it Completed and uses the reserved money to fund the transfer.

Viewing a transfer

  • The sender can see the current transfer status in their account history.

    Transfer history end-to-end test

    Account history shows Cancellation requested while a reply is pending and updates to the recorded outcome when the network responds.

    • Each history entry shows the transfer amount and destination account alongside its status.

      Transfer history display test

      The history entry shows the original amount and destination account after the transfer is completed.
