# G5-Lean implementation status (v9)

Tracker for [lean-implementation-plan-v9.md](lean-implementation-plan-v9.md), one row per PR. Created 2026-09-17 from the [v8 tracker](lean-implementation-status-v8.md), which remains unchanged. Merged rows below are copied verbatim; unmerged titles/dependencies follow v9 §5.1. P4.14 is withdrawn by the latest user scope decision; its identifier is reserved and its unmerged row removed. This documentation revision marks no implementation work complete.

- **Branch** is filled by the PR that lands the row, in the same change, with the branch name and the PR link. On `main`, a non-empty Branch means the PR is merged and an empty one means it is not; whether someone is working on a PR is not recorded here.
- **Depends on** is a copy of the Depends on column of plan §5.1, or of the earlier plan for rows already merged before v9. A PR is ready to start when every PR it lists has a non-empty Branch. A PR that changes the dependencies in the plan updates this column in the same change.
- **Notes** hold one line on what landed and the `LEAN-TODO` markers left; the PR description holds the full record.

Rows of merged PRs are never edited by later PRs.

**Readiness checkpoint:** recorded 2026-09-18 by the Platform program owner (@zcl-g5). The Workspace (@zcl-g5), Agents (@rahul-g5) and Worker & Host (@kaihuiz-g5) owners reviewed plan §2.2 and accepted its harness boundaries as written: real validators and fixture vectors for policy and protocol; the P4.4a test-support host peer and the P4.2a dispatcher/mux fixture for API/dispatcher integration; the real `g5d host` under Linux KVM for the host substrate, with a fake VMM only for deterministic unit faults; browser/API callers with fake provider binaries for user flows. Grouping decisions: none; the identifiers, sizes and dependencies of plan §5.1 stand, and P4.1 and P4.5 are reviewed in bounded internal stages. Test-only process hosting is never an isolation backend. P4.1 and the runtime PRs may start once their own dependencies are merged; the plan §6.0 gate reads this line. Revisit after P4.5/P4.11, after P4.10, or on a material interface change (plan §2.2). The current scope/review decisions are recorded in [the reconciliation note](v9-final-scope-and-review-reconciliation.md).

**Fork claim simplification:** the approved design removes the planned `workspace_fork_reservations` table. P4.1 stores immutable name/member claim identity in `workspace_forks`; P4.5 uses pending/aborting rows as the sole durable claims under canonical repo-row locks and fresh READ COMMITTED conflict checks. Recovery, private-claim exclusion and sibling-writer/deletion tests are required before implementation acceptance. Dependencies and merged rows are unchanged; this is documentation scope, not a landed runtime change.

**Data-model review:** [item-by-item response](lean-backend-design-v9-datamodel-review-response.md) and associated contract/plan changes are documentation only. Merged rows remain unchanged; unmerged dependencies follow the current scope revision.

**MVP scope amendment (2026-09-19):** for the microVM, the host and for secret and identity management the MVP keeps what the original G5 built, with credentials delivered as environment variables. The mechanisms v9 had put in their place leave the MVP and wait behind the P8.8 audits. P4.12 left the MVP and keeps its row and id as a post-MVP PR; P8.10 to P8.14 were added for the dropped scope; the Depends on cells of unmerged rows follow the amended plan §5.1. Merged rows remain unchanged. See [v9-mvp-scope-amendment.md](v9-mvp-scope-amendment.md).

**QA evidence:** not deployed or observed by this revision. Under plan §7.2, Platform records authorized checkpoint observations here with candidate commit, migration set, image digests, deploy build id, smoke outcomes and remaining gaps; these records do not edit merged implementation rows.
