# Lean MVP test-removal ledger

This ledger classifies every test file removed by the workspace-VM cutover. A removed test is not treated as passing evidence. Each row states why its old oracle is invalid and identifies retained replacement coverage or an explicit MVP gap.

Files are listed by exact path so the ledger can be mechanically compared with the branch diff. Production sources whose names happen to contain `spec`, plus prompt templates and golden input data, are listed separately from executable tests.

## In-file removal appendix

Whole-file classifications below are supplemented by [`lean-mvp-in-file-test-removals.tsv`](lean-mvp-in-file-test-removals.tsv), which records every removed Rust and frontend test name from a file that still exists on this branch. It contains 1,347 exact-name dispositions: 926 Rust cases and 421 frontend cases. Each row is classified as a retired protocol or surface, a behavior rehomed at a retained boundary, an explicit runtime validation gap, or an internal helper retired with its only producer. None of these rows is counted as passing evidence.

The TSV dispositions and evidence are review-owned text. [`audit_in_file_test_removals.py`](../scripts/audit_in_file_test_removals.py) independently extracts test names from the baseline and candidate and verifies that the ledger has one classified, evidenced row for every removed name. `--write` only reconciles the key set while preserving existing review text; it marks any newly removed test `UNCLASSIFIED` so validation fails until a reviewer supplies its disposition and evidence.

The comparison is pinned to baseline `0db478c72c32f71ec77fb7117ac8af1982337eaa` in [`lean-mvp-test-removal-baseline.txt`](lean-mvp-test-removal-baseline.txt). Run `python3 scripts/audit_in_file_test_removals.py` to prove that the appendix exactly matches the current tree or add `--write` after an intentional test change. The file-level rows below provide the domain-specific replacement evidence referenced by the appendix.
