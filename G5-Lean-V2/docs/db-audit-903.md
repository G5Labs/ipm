The [owner's read-only QA audit](https://github.com/G5Labs/G5-Lean/pull/908#pullrequestreview-5676877124) records this snapshot at **2026-10-28 01:40 UTC**:

- The SQLx ledger ends at 122, applied at 00:01 UTC that day. The earlier observation ending at 121 is superseded.
- `g5` is NOSUPERUSER/NOBYPASSRLS and owns the affected tables and `repo_webhook_secret_for_current_org(uuid)`, with the required ownership privileges. The helper's EXECUTE grantees are PUBLIC, g5, g5_app and g5_tenant.
- The serving API and daemon image was built from `ba8f76c7c` by deploy `ab95d67d`. The two prior successful deploys were `3c08927eb` and `9f1f974d0`. The compatibility floor for this cleanup is main at `f0db5e29d` (2026-10-18); serving and rollback targets must be main builds at or after that commit.
- The drops deliberately discard retained-root values on 24 `workspace_vms` rows (23 stopped, one failed; last updated 2026-10-23), non-empty `retained_roots` on 29 terminated hosts, and `max_retries = 0` on 215 of 1,815 tasks (the remainder have the default 2).
- Other selected values are default, NULL or empty: both libkrun columns on 684 hosts; retention hours of 24 on 1,159 settings rows; the three retired workspace fields on 1,159 rows; the other four task fields on all 1,815 tasks; and `linked_nodes` on 572 sessions. `repo_secrets` and `merge_evaluations` each have zero rows. The owner accepted that historical-value loss on 2026-10-28. The Helm pre-upgrade hook can run while the previous API still serves, so retain serving/rollback compatibility and external SQL/self-hosted consumer checks before deployment. Old wire fields remain intact. Reversing a drop requires restoring a backup; rolling back an application image cannot restore discarded values.

Each cleanup migration, including the artifact UUID drop, sets a transaction-local five-second lock timeout. Contention fails and rolls back that feature's migration; retry the hook after the blocking transaction ends. This bounds the time a queued exclusive lock can stall later application queries.

## Artifact UUID follow-up

PostgreSQL rejects a cached `SELECT *` result descriptor after `blob_id` is removed, even though SQLx's named `FromRow` mapping ignores the field. Reproduced on PostgreSQL 17 with PREPARE / EXECUTE / transactional DROP / EXECUTE: SQLSTATE `0A000`, `cached plan must not change result type`. The pre-upgrade hook would expose already-serving connections to that failure. This makes explicit projections a release prerequisite, not optional cleanup hygiene.

[Migration 134](../backend/g5-api/src/db/migrations/134_drop_review_artifact_uuid.sql) promotes the rehearsed SQL into the deployment catalog with its own checksum. The populated fixture applies this exact file through the restricted production runner, refuses unknown dependencies and lock contention, and retries as a no-op. Warm SQLx statements prove old star queries fail while the explicit projection retains its result shape and decoded artifacts.

Before merging this follow-up, the owner verifies that the serving release includes PR #908 (main commit `c483ca506df4d5e941ce745af7b49a03f6481bb7`), all connections prepared by earlier releases have drained, and supported rollback releases include the same explicit projections. This is a stricter compatibility floor than the earlier cleanup's `f0db5e29d`. Preparing this PR does not verify deployment; do not deploy both stages together.
