# 07 — Namespace ownership of IPM

Module root: NSP-0

Scope: where IPM lives (local install, mapping, legacy upgrade), the `enable`, `unmap`, `namespace` (`zn`),
`version` and `information` commands, the installer, and manifest system requirements. Baseline: ipm 571e04a1.
Evidence was first by inspection of source and tests at that revision. Native checks N1-N22 (intents/07-09-seed-challenge.md) were then run on IRIS 2026.1 build 234U in container `ipm-uplift-iris-nsp` (N1 in a throwaway fresh container); `O:` tags name their observations (logs `validation/logs/8*-nsp-*.log`), `T:` tags name IPM test classes run here (log 892-nsp-ipm-tests). Model evidence (round 3): `P:` tags name lemmas of `models/verus/ns_mapping.rs` (premises in Notes; trust items in `models/verus/ns_mapping.TRUST.md`), `M:` tags name checks of `models/explorer/nsp/check.py` (`evidence/model-checks-nsp.json`); model probes are `nc-nsp-model-*` (logs `validation/logs/85-87-nsp-model-*.log`).
