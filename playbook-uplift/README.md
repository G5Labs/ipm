Target: `ipm` at `571e04a19aba9f9b4bc0ea23fbe09182038f4e55` (tag v0.10.11-beta.28). Workflow:
`omnisaas/playbook/verification-playbook.txt`. Starting evidence: `docs/ipm-uplift/index.md`. Run date: 2026-11-13.

simplifications and open questions; it fixes nothing. The two probe patches (p8a, p8b) were applied only to throwaway

## Evidence levels used throughout

- **Proved**: Verus, about a hand-written model of the IPM code, under named premises, with mutation controls killed.
- **Model-checked**: Python explorers and cross-checks, bounded.
- **Observed on IRIS**: real IRIS Community 2026.1 (load/history also 2025.3) running the pinned IPM.
- **Inspection**: read in the code only.

Intent (what IPM *should* do) comes from IPM's help, comments, README, wiki, changelog, tests, git history and GitHub
discussion; where none settles it, the run states an assumption and its alternatives (`QUESTIONS.md` Part A).

## Database

IPM keeps its state in IRIS globals. There is no PostgreSQL, so the playbook's pgspec library does not apply and was
not used; an IRIS environment contract built here plays its role and is validated against IRIS itself.

## Reproduce

```bash
scripts/full_rerun.sh
```

Reruns every proof, control, model check, evidence collection and gate from the recorded IRIS logs (log:
`validation/logs/49-full-rerun.log`). Rerunning the IRIS checks themselves is per lane: `scripts/iris_sync.sh` and
`scripts/iris_run.sh <script> <log>` with `CONTAINER` set.

Containers left running: `ipm-uplift-iris`, `ipm-uplift-iris-inst`, `ipm-uplift-iris-repo`, `ipm-uplift-iris-nsp`,
`ipm-uplift-oras` (network `ipm-uplift-net`).
