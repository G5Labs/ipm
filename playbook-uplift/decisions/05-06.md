## Observed facts for these decisions (native checks, IRIS 2026.1, IPM 571e04a1)

The decisions stay open. These are what IRIS did when the current code ran; observation names refer to
`evidence/iris-observations.json` (logs `validation/logs/7*-repo-*.log`).

- **DEC-UNIN-1:** `uninstall nc-web-dep` while `nc-web-top` needs it returned OK, printed "Clean SKIPPED - required by
  1 other module. (nc-web-top)" and then "Clean SUCCESS", kept the module, deleted its web app `/nc-dep`, and logged
  `uninstall/success` (`nc-unin-1-blocked-uninstall`). Option (a) would also need the web-app deletion moved after the
  dependent check (F-UNIN-1).
- **DEC-UNIN-2:** `zpm clean` with 2 other modules returned OK, printed "WARNING: 2 module(s) orphaned" and "Reinstalling
  IPM will automatically re-adopt these modules.", and removed nothing: IPM classes, IPM's record and both modules stay
  (`nc-unin-9-clean-on-ipm`). No self-uninstall flag was left set.
- **DEC-UNIN-3:** not checked natively (no scoped-dependency case was run).
- **DEC-REPO-1:** with one remote registry holding a token and no publish flag, `publish nc-repo-pub -v` chose it and
  printed "Publish to: http://127.0.0.1:9/"; it failed only on the TCP connection (`nc-repo-1-publish-no-flag`).
- **DEC-REPO-2:** for a disabled ORAS registry, `search` listed it and its module, `publish -r` to it succeeded (tag
  pushed), install did not use it, and unpublish refused it with "Repository 'nc-repo-o2' is unavailable."
  (`nc-repo-2-disabled-registry`).
- **DEC-REPO-3:** after changing only the URL, an ORAS registry kept user `u` and its password; a remote registry
  cleared both (`nc-repo-3-url-change-credentials`). Also observed: a remote registry may not take a URL that an ORAS
  registry already uses ("Repo 'nc-repo-o3' already uses this URL.").
- **DEC-REPO-4:** `config set NoSuchKey 1`, `config get NoSuchKey` and `config set TestReportFormat xml` all returned OK;
  the last printed "Unknown format 'xml'" and stored nothing (`nc-repo-8-config-errors`).
- **DEC-REPO-5:** a module with a `Deploy="true"` resource was pushed only as tag `1.0.0__2026.1`;
  `unpublish nc-repo-o9/nc-repo-dpl 1.0.0 -force` failed with "'nc-repo-dpl' 1.0.0 not found in repo 'nc-repo-o9'." and
  the platform tag stayed; `unpublish ... all -force` removed it (`nc-repo-9-unpublish-deployed-version`). So today a
  deployed version cannot be unpublished by version at all, only with `all`.
- **DEC-REPO-6:** `-password-env NC_PW` and `-token-env NC_TOK` stored the secret values in plain text in
  `^IPM.Repo.DefinitionD`, not the variable names; `repo -list` did not print them (`nc-repo-13-secret-at-rest`).

## Resolutions (2026-11-13)

Each decision above was resolved from the round-4 intent research in `decisions/research/`. RESOLVED-EVIDENCE: an
authoritative source settles the intent. RESOLVED-ASSUMPTION: no such source; the most reasonable intent was
chosen and the alternatives are kept here. The Status column carries the verdict. Statements that waited on a
decision no longer carry `OPEN`; where the code contradicts the resolved intent they carry `F` and `O!`.

### DEC-UNIN-1
- **Verdict:** resolved (evidence).
- **Resolution:** Option (a): a blocked uninstall without -force returns an error that names the dependents and its history row is a failure. A need kept by `uninstall X -r` is documented and does not fail the command (but its row must not claim a removal).
- **Key sources:** Issue #58 (maintainer: 'block and warn'); skipped test InstallModule.cls#L132-L159; PR #912; Base.cls#L276 comment; help Main.cls#L486-L487; wiki 01 CI use of %Status. PublishModuleWithDeps.cls#L25-L26 predates the block.
- **Code matches:** No: F-UNIN-6 stands (UNIN-B30, new UNIN-B84); UNIN-B85 states the -r case.
- **Research:** decisions/research/repo.md#dec-unin-1--blocked-uninstall-fail-or-succeed

### DEC-UNIN-2
- **Verdict:** resolved (evidence).
- **Resolution:** Option (b): `zpm clean` is an ordinary level-0 Clean; the orphan warning, full cleanup and self-uninstall handling belong only to a real removal of IPM (Clean.Level>0).
- **Key sources:** Lifecycle/Module.cls#L27 comment; Storage/Module.cls#L630, #L647; PR #1106; wiki 00 and 02 Clean.
- **Code matches:** No: new F-UNIN-11 (UNIN-B70, new UNIN-B86).
- **Research:** decisions/research/repo.md#dec-unin-2--zpm-clean-clean-on-ipm-itself

### DEC-UNIN-3
- **Verdict:** resolved (assumption).
- **Resolution:** Option (b): a need declared only for a phase does not make its owner a dependent and does not block uninstall. The decision row's premise was wrong: uninstall, `show` and `list-dependents` already agree.
- **Key sources:** Utils/Module.cls#L615; Storage/Module.cls#L834-L855, #L955; Scopes.cls#L26-L41, #L108-L129; PR #1315; IRIS r4-repo-unin3-*.
- **Alternatives and what would change:** (a) count scoped needs, protecting a test dependency loaded from a folder; it would need GetDependentsList to pass all phases and `show` to list them, turning three readers into defects. (c) display only.
- **Code matches:** Yes. UNIN-D2, UNIN-B34 restated; new UNIN-B87 (-r removes scoped needs).
- **Research:** decisions/research/repo.md#dec-unin-3--do-phase-scoped-needs-block-uninstall
