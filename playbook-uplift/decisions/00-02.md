## Resolutions (2026-11-13)

Each decision above was resolved from the round-4 intent research in `decisions/research/`. RESOLVED-EVIDENCE: an
authoritative source settles the intent. RESOLVED-ASSUMPTION: no such source; the most reasonable intent was
chosen and the alternatives are kept here. The Status column carries the verdict. Statements that waited on a
decision no longer carry `OPEN`; where the code contradicts the resolved intent they carry `F` and `O!`.

### DEC-SYS-1
- **Verdict:** resolved (assumption).
- **Resolution:** Lexical scope (option A): a statement may use a term defined by an ancestor, or by an earlier sibling of itself or of any ancestor; a child inherits what is in scope for its parent.
- **Key sources:** playbook section 3.1 (verification-playbook.txt#L216-L229): define before use, ancestors and earlier same-level statements; the strict reading gives 1040 violations in 585 statements on this ontology.
- **Alternatives and what would change:** (B) strict reading: every module would need its definitions re-parented into a chain above all behaviours, or repeated. Would change: the index script's ancestor-sibling clause and most module layouts. Suggested playbook sentence: 'A child may also use any term that is in scope for its parent.'
- **Code matches:** Yes (scripts/ontology_index.py implements A). No ontology change.
- **Research:** decisions/research/hist.md#dec-sys-1--lexical-scope-for-definitions-first

### DEC-HIST-1
- **Verdict:** resolved (evidence).
- **Resolution:** Keep them (option A): a dependency record survives the parent's rollback, keeps its own Success and reads Committed = 0.
- **Key sources:** PR #578 (TODO 'Record recursively loaded/installed modules'; history saved 'outside of the transaction'); AbstractHistory.cls#L4; wiki 09 ('Committed vs. Success').
- **Code matches:** No: F-HIST-1 stands (HIST-B19, new HIST-B32).
- **Research:** decisions/research/hist.md#dec-hist-1--dependency-records-when-the-parent-rolls-back

### DEC-HIST-2
- **Verdict:** resolved (evidence).
- **Resolution:** Once a load's changes are durable, its record must read Committed = 1, even after a crash or restart. Option A (save the durable row when SetCommitted runs at $TLEVEL 0) is the simplest fix; the fix design is an implementation choice.
- **Key sources:** SetCommitted comment AbstractHistory.cls#L119 (PR #1322); issue #1237; property comment #L41-L42; wiki 09.
- **Code matches:** No: F-HIST-2 and F-HIST-8 stand (HIST-B11); Part B U19 adds a graceful-stop instance (r4-hist-graceful-stop-txn-after).
- **Research:** decisions/research/hist.md#dec-hist-2--committed-after-a-crash-or-restart-once-a-developer-mode-or-no-transaction-load-kept-changes

### DEC-HIST-3
- **Verdict:** resolved (evidence).
- **Resolution:** A record of a command that ends names the module and version whenever IPM could read them from the manifest; the name may be empty only when it was never known. A crash may leave placeholders.
- **Key sources:** wiki 09 Package and Version columns, 'dies mid-install'; AbstractHistory.cls#L14, #L72; History.cls#L251-L299 test; Utils/Module.cls#L1207 vs #L1293.
- **Code matches:** No for refusals: F-HIST-5 narrowed (HIST-B7); crash records match (new HIST-N4).
- **Research:** decisions/research/hist.md#dec-hist-3--must-a-record-name-the-module-once-ipm-read-the-manifest

### DEC-HIST-4
- **Verdict:** resolved (assumption).
- **Resolution:** Allow it (option B): the command's work and its record follow the caller's transaction; if the caller rolls back, both are undone. Document it, and add a caveat to the wiki's 'outside the transaction'.
- **Key sources:** wiki 00 (-DNoTransaction=1 for an 'outer wrapping transaction'); Utils/Module.cls#L1162, #L1358-L1361 (built for nesting); no source discusses a caller rollback.
- **Alternatives and what would change:** (A) refuse when $TLEVEL > 0: breaks documented outer-transaction use. (C) write the record outside the caller's transaction (job or IRISTEMP reconciled later): audit-grade trail, but Committed must be recomputed. If C is chosen, F-HIST-3 is a code defect again and HIST-N1 is restated.
- **Code matches:** Yes: F-HIST-3 becomes a documentation gap (HIST-N1, LOAD-N1 now O and P).
- **Research:** decisions/research/hist.md#dec-hist-4--commands-started-inside-a-callers-transaction

### DEC-HIST-5
- **Verdict:** resolved (evidence).
- **Resolution:** Committed describes database changes only (option A); file effects are not covered and this should be documented.
- **Key sources:** PR #578 review (Committed is about changes 'made to the database'); PR #1322; AbstractHistory.cls#L41; wiki 09.
- **Code matches:** Yes. F-LOAD-3 stays a separate defect (wiki 00: a failed normal load rolls back).
- **Research:** decisions/research/hist.md#dec-hist-5--does-committed-cover-file-changes

### DEC-HIST-6
- **Verdict:** resolved (assumption).
- **Resolution:** The delete wins (option A): an operator may delete any record, finished or running, and the command then ends without one. A delete of a row locked by an open transaction may fail with a lock error; that is acceptable.
- **Key sources:** PR #578 (only inserts and deletes allowed; History.cls#L15-L22); wiki 09 `history delete -confirm`; IRIS r4-hist-delete-* runs.
- **Alternatives and what would change:** (B) a running record cannot be deleted (guard on TimeEnd empty and HistoryTemp present). (C) re-create it at close (PersistToTwin re-inserts). If B or C is chosen, F-HIST-10 is a defect again and HIST-B33 is restated.
- **Code matches:** Yes for rows saved at $TLEVEL 0: F-HIST-10 becomes intended (new HIST-B33, HIST-N5).
- **Research:** decisions/research/hist.md#dec-hist-6--history-delete-of-a-running-commands-record

### DEC-LOAD-1
- **Verdict:** resolved (assumption).
- **Resolution:** Document it as an operator error (option A); IPM does not guard against a commit at a crash prompt.
- **Key sources:** No IPM source; the prompt is IRIS terminal behaviour (SYS-D16); wiki 00 assumes the transaction is not committed by hand.
- **Alternatives and what would change:** (B) mark the log committed before each region a halt could commit: honest record, more writes, blurs Committed for normal crashes. (C) run loads in a job: changes interactive behaviour. If B is chosen, F-HIST-4 is a defect again.
- **Code matches:** Yes: F-HIST-4 becomes documentation (HIST-N2, LOAD-N2).
- **Research:** decisions/research/hist.md#dec-load-1--operator-commits-at-a-crash-prompt

### DEC-LOAD-2
- **Verdict:** resolved (evidence).

- **Key sources:** Utils/Module.cls#L1305-L1307 since the 2021 import (9713db77); help -nodev Main.cls#L307; wiki 00 Developer Mode.
- **Code matches:** Yes for load (LOAD-B21). The update path clears it from a registry (Utils/Module.cls#L309-L310): added to F-INST-5.
- **Research:** decisions/research/hist.md#dec-load-2--a-plain-load-over-a-developer-mode-module

### DEC-SEM-1
- **Verdict:** resolved (assumption).

- **Alternatives and what would change:** (B) clear it at the end of each command: Validate/ReportConflicts would then see only the current command's resources. Would change: semantics/coverage.json INV-TEMP entries become findings.
- **Code matches:** Yes. semantics/coverage.json INV-TEMP verdicts updated; no ontology statement.
- **Research:** decisions/research/hist.md#dec-sem-1--iristempipmloadedresourced-after-commands

### DEC-SEM-2
