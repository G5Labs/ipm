# Boundary model premises

`boundaries.rs` is a hand translation and finite provider contract. None of the ObjectScript bodies is mechanically proved. The eight Verus proof items have no `assume`, `admit` or `external_body`; the ports below are inputs rather than solver axioms.

- History models one temporary row and its permanent twin. `Loss::Process` means abrupt SIGKILL of the holder, not a graceful HALT or `$SYSTEM.Process.Terminate`, which may run close callbacks. `Loss::Instance` drops temporary storage. The permanent row survives only when `durable_database=true`; arbitrary power loss, disabled journaling and restart in another open transaction are not proved. The disposable restart observation retained the initial permanent snapshot, not the temporary name change.
- Two delete/finalize schedules are represented, not all concurrent executions. `save_after_delete=false` and `replay_on_close=true` encode the measured IRIS persistence outcomes for these fixtures. The accessible twin is deleted before its temporary copy is finalized. In the locked schedule, a child SQL delete waits while the parent finalizes/persists, then runs after unlock/commit, and the later temporary close writes the original twin ID again. Native observations validate this table; the Verus proof reasons about the table and does not derive IRIS object-cache semantics.
- Lock depth is an arbitrary natural number. A deferred unlock survives nested transaction ends and ends at the outermost transaction end; immediate release ignores transaction depth. Native observations cover depth one and the constructor's two modes. The actual repository `BuildCache` source uses default `%New()` (immediate=true), commits its local transaction, and then closes its local manager at method return. The new model's `cache_return` represents this explicit lock. Database cache isolation and incidental provider locks are not proved.
- CPF has an explicit child exit and an independently supplied final configuration value. Status success does not prove a configuration value. Database rollback preserves that externally supplied value. The native valid fixture creates one disposable role through the actual `DoMerge`; the invalid neighbor uses an unknown CPF section and exits 7. The role is read through `Security.Roles.Exists` before, during and after rollback. Other actions, partial merges, restart requirements, privileges, macros, path normalization and other error paths remain open.

The state bounds are one row/twin, two fixed delete schedules, two named loss kinds, a Boolean configuration role and a scalar database sentinel. They are not a complete restart refinement, scheduler model, filesystem model or CPF implementation.

`native_driver.py` creates a fresh container from local image SHA `8db58b93cf76245f6cc9cfc16aaa9627391535eab6350134ecc1bbf8bcf8b82f`, freezes fixture inputs, records commands, and restarts only that disposable container. Existing shared containers are excluded. Raw failed discovery runs are retained separately and earn no correspondence credit.
