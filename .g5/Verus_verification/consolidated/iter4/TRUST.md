# Iteration 4 trust and claim boundary

These are input-driven Verus hand translations, not verified ObjectScript. `implementation_proofs = 0`. A passing run proves the stated properties of these representations and the generated native comparison assertions. It does not prove unobserved executions of IPM. No `assume`, `admit`, `external_body` or trusted theorem is used.

A control counts only when Verus rejects an assertion or postcondition. Parse errors, missing tools, resource limits and timeouts do not count. The native replay never uses an observed value as a model input: each assertion compares a model result computed from the fixture's inputs with the observed field. One field per model is flipped and must be rejected.

| Boundary | Representation and scope | Evidence and residual |
|---|---|---|
| Result rows | `Row` is BuildResultTree's classification: case error, method error, failed assertion, and rows that are not failures. A method error exists only for a failed method with an error category. | Native fixture with a thrown error, two failed assertions and a failing `OnBeforeAllTests` gives "4 failure(s)". %UnitTest's own row writing and skipped-status values are not modeled. |
| Result list | `Slots` are the process-private entries; `None` is an empty slot. Start positions come from the caller. | Native A1-A4 and D1-D3 use real result indexes in seeded slots. A real `verify` nested inside a running test method was not executed. |
| Resource outcome | Booleans for selection, a named Suite folder's existence, whether the package has classes, `RunTest` status and report extension support. Ordering of resources is the module's resource order. | Native T1-T6 with three resources. Suite folders that exist but are empty, `ManagerClass` overrides and `verify` namespace cleanup errors are source-only or open. |
| Aggregation | `test` calls every in-scope resource; `sync -test` calls resources until the first failure. | Native for `test`; `sync -test` is source-only (`SyncRunTests`). |
| Exit code | Exit 1 iff the command failed and the terminate flag is set. | Native E1-E4 through `iris session` with a routine argument. Other process launch methods are not covered. |
| Registry requests | Origins are host and port. Credentials are "Basic complete" and "token present". Headers come from `GetHttpRequest`. | Two-origin plain-HTTP provider inside the container recorded headers. TLS, redirects (`FollowRedirect=1`), proxies and production registries are open. Token auth method other than the default `apiKey` was not exercised (see P:F-REPO-1). |
| Integrity | `digest_lower` is the lowercase SHA-1 text; the registry hash is compared exactly; empty skips. | Native same, mismatch, uppercase, empty-hash, 404 paths and three full installs. SHA-1 computation itself and temporary-file cleanup are not modeled. |
| Install chain | Download error, gzip success and manifest presence are inputs; C:D18's empty extraction appears as `gzip_ok=false`. | Native good, mismatch and empty-hash junk installs with the provider log showing which installs sent analytics. Dependency resolution and lifecycle phases after a good download are not modeled. |
| Sync recompile | Resources carry compilable, Compile scope, project-compiled and resolution-success flags plus class children with a defined flag. | Native Y1/Y2 call the real private step through a subclass with a fixture processor whose resolution fails on demand. The full `sync` command, hash commit and file routing are source-only. |
| Producers | Lifecycle class enumerates Module, DeployedModule and a subclass with its own default. Phase admission is the `VALUELIST` of the Test processor's `Phase`. Keywords are plain text, `$list` or a list object. Path conversion uses character codes. | Native compiled parameters, a real Test processor's validation and `TestsShouldRun`, and the real private path converter. Keyword tokenization has no new native case. |

Proposed functions prefixed `repaired_` are separate from as-built behavior. Their proofs do not mean the product was repaired. Iteration 3 files are unchanged; `repairs4.rs` supersedes the iteration 3 phase and deploy readings only for the named cases, and `lemma_admitted_agree` shows the iteration 3 phase reading is correct on admitted declarations.
