# Iteration 3 trust and claim boundary

These are input-driven Verus hand translations, not verified ObjectScript bodies. `implementation_proofs = 0`. A successful Verus run proves the stated specification properties and the generated native comparison assertions under these representations; it does not prove unobserved executions of IPM.

No new `assume`, `admit`, `external_body` or trusted theorem is used. The negative controls change actual guards or writers in copies of the maintained models. A control passes only when Verus rejects an assertion/postcondition, not for parse errors, missing tools, resource limits or timeouts.

| Boundary | Representation and scope | Evidence and residual |
|---|---|---|
| Dynamic JSON / text | Parsed anonymous-filter fields; scalar strings, operator objects and arrays are distinct. Duplicate object keys have already been resolved by the JSON decoder. ASCII text without newline uses literal punctuation and `*`/`?`; stored provider property arrays become sequences. | Native parser, wildcard and selection contrasts. JSON decoding, Unicode/ICU matching and all nonstring coercions are outside the model. |
| Artifact paths and timestamps | Selection sees the repo/name/folder obtained from a normalized provider path. Empty folder becomes dot for matching. Timestamp comparison is lexical and keeps first on equality. | Native root paths, required properties, unsorted results and ties. Parsing arbitrary malformed paths, clocks/timezones and provider truthfulness are open. |
| Authenticated AQL | Actual request includes a token before Basic, or anonymous on incomplete Basic. The authenticated response is accepted in provider order. | TLS provider records request headers and reversal of the returned list. The provider's AQL filtering/order is an explicit premise, not proved by the requester. |
| HTTP authentication | `provider_status` models a disposable same-origin server with a valid credential of the named kind required on both endpoints. It derives 200/401 from request construction, not from an expected result input. | Native Bearer metadata 200 followed by credential-free bytes 401, public-byte success and real Activate failure/success. Arbitrary credentials, redirects, TLS trust policy and production providers are open. |
| Filesystem | `save_download` distinguishes existence and contents; `copy_export` is a successful overlay over one resource's destination with separate siblings. | Native stale same-name file, retained unrelated destination/sibling files, valid extraction and real copies. Partial OS copies, links, path traversal, protected-target policy, races and compensation remain open. The native CopyDir documentation corrected the initial replace-directory assumption. |
| Gzip / tar header | `HeaderRead` is the decoded first header with read status, name and calculated/stored checksum. Status is a separate field; the kernel derives stop/reject/entry. | Native invalid gzip returns empty data plus error; wrapper accepts. A bad checksum is refused. Gzip decoding, checksum arithmetic, later entries, PAX and file-body writes are not proved. The proposed read-status repair is proved only at this decision boundary. |
| Resource defaults | Numeric maps encode selected literal property values and conditions. Explicit attributes are a distinct set, including explicit empty values. Each default reads the current state. | Native ordered/chained defaults and explicit-empty protection; generic frame property for any explicit value. Non-equality comparisons, expression evaluation, aliases and dynamic datatype conversion are source-only. |
| Resource order | `ordered_before` models the pairwise comparison of ordinary textual document stems and placement before path/other resources. | Exact source sorting keys. Full list construction, collation and stable-sort refinement are not proved. |
| Deployment / project loading | Class/parameter existence and exact parameter value are separate inputs. Installer status and other save checks are provider results; the fresh-resource unique-name guard is derived from identity and stored names. Object flag, stored flag and success marker are separate state. | Native parameter false versus resource true, Module/DeployedModule defaults, corrupt-project error with stored flag true and no marker, versus duplicate-reference save error with object true and SQL false. Successful installation marker and shared-path reuse are source/formal only. Provider partial writes are not erased by a false status. |
| Project check / export | `export_item` models the actual status overwrite before source fallback. `check_project` filters missing items; other provider errors remain a separate final status. | Actual inherited exporter with a controlled failing override plus real source export. Native missing item is removed and Check returns OK. No natural default-helper failure in a complete package command was established. |
| System requirements | Health is unset/false/true, interoperability is an independent capability, namespace is literal text. Concrete check failures are derived from those inputs. | Inherited native check bodies with a controlled environment subclass; existing integration tests support omitted/explicit Health. Runtime detection and version expression algorithms remain their existing ports and defects. Full six-check aggregation and exception composition are source-only. |
| Public repairs | Invoke return-type metadata is resolved to status/nonstatus; CheckStatus is tri-state. Repository kind, enabled state, keywords and command-local denial are distinct inputs. Settings carry current and first default. Test selectors preserve a defined-empty Suite. | Native relevant returned-error, filesystem search, settings and selector contrasts. Locking/concurrency, arbitrary failing storage writes, full CLI parsing, argument evaluation and complete test/sync execution remain open. |

Proposed functions prefixed `repaired_` are separate from as-built functions. Their preservation/refusal proofs do not mean a product repair was implemented or verified. Canonical registers preserve that distinction. Existing successful behaviors and exact iteration 2 withdrawals are retained byte for byte.
