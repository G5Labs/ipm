# implementation · iter70

Repairs the iteration 69 transcription of the #281 implementation and binds it to the final candidate.

- The repo definition's trust server is the active policy identity. Its writers, its readers in copies, lock files and both services, and the refusal for other repository types.
- IPM chooses which server notary asks (`invoked_server`). That notary checks the answer against the root pinned for that server is the premise `notary_verified`, not an IPM guard.
- notary list with the docker roles, parsed to the first trusted row per tag.
- Removing the cached timestamp before notary runs turns notary's offline fallback into a failure.
- One SignedTargets outcome per repo, trust server and repository for the rest of a shell command. After a timeout, the repo's other repositories on that server fail without notary.
- The catalog offers only signed tags and reads metadata from the manifest fetched by its signed digest.
- The protected payload path from the signed row to the stream IPM loads. The Python helpers hash the bytes they write.
- A refusal reaches the loader as a failed status before the archive is unpacked or the installed root is replaced.

The proofs verify models. All product correspondence is by transcription with native agreement. No ObjectScript or Python body is verified.
