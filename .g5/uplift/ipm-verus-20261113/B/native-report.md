### Runner and evaluator

- `VV/native/run-iris.sh` keeps its watchdog, receipt and `NATIVE-END` rules. One extension was made during this phase: each `exec` now copies `VV/native/cases/*.json` into `<run>/inputs/` before the session starts and records `expectations_snapshot_sha256` in `receipt.json`. This makes it checkable that expectations preceded the run (see section 8 for the runs before the change).
- `VV/native/evaluate.py` (run with `python3 -I`) parses `OBS <case> <field>=<value>`, `CASE-BEGIN` and `CASE-END` lines and writes `verdict.json` with expected value, source, observed value, per-field match and an optional `predicted_as_built` comparison. Process outcome and substantive verdict are separate fields. A missing field, a failed harness field, a missing case marker, a non-COMPLETED process or a license/disk message makes a case INCOMPLETE. `--mutate CASE:FIELD=VALUE` flips one observed field and records whether the evaluation changes (`mutation_controls`).
- `VV/native/evaluate_suite.py` gives PASS, FAIL, INCOMPLETE or NO-EFFECTIVE-TESTS for a product `%UnitTest` suite from the method rows and IPM's own summary line.
- Helper classes (not product code), loaded into USER of the disposable container: `VV/native/scripts/B2Native/Util.cls`, `Premise.cls`, `CloseProbe.cls`, `Cases.cls`. Terminal scripts: `VV/native/cos/*.cos`. Fixtures: `VV/native/fixtures/*/1.0.0/` generated by `VV/native/make_fixtures.py` (hand-written XML starts with `<Export generator="IRIS" version="26">` and each module.xml cites the product fixture it adapts). Expectations: `VV/native/cases/expected-premises.json`, `expected-premises-2.json`, `expected-cases.json`, `expected-repro.json`.
- Every run is listed in `VV/results/index.jsonl`.

## 7. Refuted hypotheses and corrected premises

- N-P10 refuted. `$SYSTEM.Process.Terminate` runs `%OnClose` (and `HALT` does too, N-P11). For a non-dev load the destructor runs before IRIS rolls the transaction back (C1). This refutes three statements for the Terminate path:
