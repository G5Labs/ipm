# IPM intent inventory (stage A1)

Locates human intent for the IPM uplift. It is evidence, not a governing specification. Product pin `571e04a1` (tag `v0.10.11-beta.28`, manifest `0.10.11-SNAPSHOT`); wiki `781e98fd` (2026-11-04); GitHub read 2026-11-13. File:line locators are at `571e04a1` and relative to the IPM checkout unless prefixed `wiki/` (the `../ipm-wiki` copy). Sources are listed in [sources-intent.md](sources-intent.md).

Authority classes:

- **a** explicit human commitment: README, CHANGELOG, wiki, CLI help or examples in `Main.cls` `XData Commands`, user-facing messages, issue or PR text and comments by maintainers. Quoted or faithfully paraphrased.
- **b** inference from attributable human sources.
- **c** agent design choice or necessary implication.
- **d** observed implementation or test behavior with no stronger human authority. Tests are maintainer expectations, but they are graded d unless a human statement backs them.
- **e** proposed improvement.
- **f** unresolved intent, carried as a `Q-nn` with a provisional option.

"Hypothesis" marks a code-reading conclusion that stage B must confirm natively before it is treated as observed behavior.

Note on PR authorship: the bodies of PRs #1322, #1268, #1308 and #1319 end with "Generated with Claude Code". All four were opened by maintainer `isc-dchui`. #1322 was approved by maintainer `isc-kiyer`, and the other three were self-merged. They count as accepted maintainer scope (a), but the wording is AI-assisted.

## 6. Conflicts, stale and superseded statements

Loading and history:

1. `-confirm` help says it "will delete all records in the current namespace" (`Main.cls:825`). The wiki (wiki/09 L46) and the code (`Main.cls:4165-4167`) treat it as a gate for unfiltered deletes (Q-11).
2. Help example `history find -DSucess="0*"` is misspelled (`Main.cls:832`). The wiki uses `-DSuccess` (wiki/09 L110, L218).
3. wiki/09 L80-86 (2026-09-03) explains `Committed` only through dev mode. It predates PR #1322 and omits `NoTransaction`/`NoJournal` and the early-failure window. The changelog (L45) and the property comment are current.
4. Superseded `Committed` rules: #366 ("0 in non-developer mode if installation fails; 1 otherwise"), PR #578 r2585373293 ("in developer mode, committed will be set to 1 regardless"), and the pre-`5d27e15b` property comment.
5. Superseded scope: #366 `Namespace` field and the 2024 shared-table decision in PR #578, replaced by per-namespace storage (INT-HIST-16).
6. `AbstractHistory.cls:20-27` says the source is empty for load. Dependency records labeled `load` carry one (`Utils/Module.cls:69`), and display shows `n/a` (Q-15).
7. wiki/09 L112 recommends filtering on `Version_Major` etc. The filter parser rejects names with `_` and drops the remaining filters (`History.cls:103-105`) (hypothesis, Q-10).
8. wiki/09 L161 reads a phase without an end as never finished. A returned (not thrown) Invoke error may leave the phase open (hypothesis, Q-14).
9. wiki/00 L126 says a failure "rolls the namespace back to its previous state". Filesystem and OS effects are outside the transaction (Q-04).

11. wiki/03 L261 says requirements are "validated before module installation". A `-dev` or `NoTransaction` load writes the manifest first (Q-17).
