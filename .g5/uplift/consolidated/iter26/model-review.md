## Decision, store and reader

The model represents one process-private `^||IPM.Sync.Summary` projection: active state, per-module SkippedCount and `(module,numeric sequence)->class` rows. It is not a persistent SQL table and has no opaque row IDs. Begin clears the tracked store and activates it; End clears it and deactivates it. AddSkipped checks the actual active state, increments the selected module's count and writes the class at that returned sequence. Module and class are exact arguments, with no validation or deduplication invented. Numeric arithmetic is the legal Boolean/nonoverflow SDK domain qualified by the small native sequence, not a generic numeric-coercion or concurrency proof.

Generic inactive, append, clear and well-formedness properties establish the actual data dependence. Separate counters survive module interleaving. Repeated classes occupy distinct numeric slots. `well_formed` gives the generated-prefix invariant: every module has exactly numeric rows1..SkippedCount. Begin/End establish it and AddSkipped preserves it. That invariant is required for the count-bounded report walk to correspond to the production `$order` enumeration. Arbitrary corrupted/manual stores, nonnumeric keys, holes or rows beyond the counter are not covered.

The Report contract projects skipped rows only. It follows supplied module order, then ascending numeric sequence, preserving duplicate class values. It does not prove full headers, formatting, files, errors, test tallies, warnings or aggregate counts. A skipped count suffices for its module section in generated stores. `module_count` is counts-domain size only for the **direct skipped-only API stores**; other Summary methods can create real module buckets without SkippedCount, so this is never an actual CLI total-module-count claim. `after_report` is an identity projection justified by source inspection and independent native before/after reads, not a mechanical proof that the ObjectScript body has no mutations.
