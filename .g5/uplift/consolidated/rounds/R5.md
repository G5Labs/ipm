## The two questions

**What consequential outcome can IPM distinguish that our model cannot?** What a module reads from its environment
files: merge order, what a failing file leaves, OS-variable values, what the next command in the same shell sees, and
whether code generated at compile time sees the configuration. No inherited model represents any of it (G has an
ontology block; P excludes it by name).

**What wrong outcome could our checker still accept?** (a) "A later command in the same session sees the earlier
`-env` values" — false: every command that runs phases clears first (S1). (b) "A failing second file keeps the
first file's values" — false (U3). (c) The held-back case: "loading a lower version is always refused" — both G
(`cur.ver > p.ver` on a `u8`, `model.rs:456`) and P (integer versions, trust item D10) predict refusal for
`2.0.0-beta` then `1.0.0-rc`; IPM installs `1.0.0-rc` (HB2).
