## The two questions, answered from product sources first

**What consequential outcome can IPM distinguish that our model cannot?** The repository registrations a load leaves
behind and which copy of a dependency it installs. `Main.LoadInternal` and `LoadModuleReference` wrap the load in a
temporary `.modules` repository (`General/TempLocalRepoManager.cls`). G models this as one boolean `cleanup_fails`;
P excludes it (premise PM). Neither represents skip-when-covered, naming, the cleanup message, or the tie between an
older repository and `.modules`. Second, the install-time expression evaluator (`%Evaluate` and helpers), which
decides file targets, invoke arguments and the after-install message, and whose failure after the final commit is
P:F-LOAD-4. Neither arm models it.

**What wrong outcome could our checker still accept?** (a) "`.modules` is searched first" — G's ontology said so, and
G I2 built on it. (b) A resolved resource whose compiled-class descriptor exists but which does not run. (c) "an error
means nothing was kept" for errors raised after the commit. (d) An evaluator that silently fills `$`-valued parameters.

## Distinguishing cases and their valid neighbors

| Wrong outcome | Rejected by | Valid neighbor accepted |
|---|---|---|
| `.modules` copy wins a tie | TR5 (older `reg5` copy installed) | TR5b (higher version in `.modules` wins) |
| leftover `ipm-temp-modules-1` is deleted or reused | TR3 (new one is `-2`, leftover kept) | TR2 (temporary repository removed) |
| an existing repository with the same root is replaced | TR4 (`keepme` used and kept) | TR1 (no folder, no repository) |
| a late error rolls the load back / reports success | TR7, P2txn/P2notxn/P2dev (`status=ERR`, module present, `committed:1`) | TR7b, P1, P3 (status OK) |
| impossibly broad rollback | R2notxn, R2dev (both classes kept), Ddev (parent kept) | R2txn, Dtxn (all rolled back) |
| compiled descriptor means usable | R2notxn, R2dev (`TwoRes*.B compiled:1 runs:err`) | R2ok (both run) |
| `$` in a value substituted literally | E32 raises `<REGULAR EXPRESSION>` | E33 (same module, other value), E34 (backslashes kept) |
