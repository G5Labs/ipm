# Checker calibration, round 1

Question: do the two inherited verification checkers accept plausible wrong observations of a load, and do they still accept the valid neighbor of each? Product `571e04a1`. No IRIS session or container was used. Every run below reads a copy of a recorded run or log, edited at the named fields only, and runs the unmodified inherited checker from a copy. Nothing under `src/`, `tests/`, `.g5/` (other than this file) or `playbook-uplift/` was changed.

A checker rejects a wrong observation only when its verdict changes to DEVIATES, FAIL, DISAGREES, VIOLATES or a failing record because of the edited field. A verdict that changes for another field, or to INCOMPLETE because a field is missing, is not counted as a rejection for the intended reason.

## What earlier work already established

- The follow-up audit of `native/evaluate_replay.py` (`uplift/ipm-quality-followup/closure.md` R01–R03, `audit-validation.md`) found that its L1 `installed` check ignores resources (R01a), that repeated observations overwrite each other (R03c), and that `Committed` uses one any-slot `kept` (R02a). Its replacement `followup/replay/evaluate_replay2.py` fixes these.
- The independent review's mutants `M1`…`M15` (`review/scratch/mutants/`) delete single checks from `evaluate_replay2.py` and `l1sem.py` and rerun that evaluator's own control families. They test the corrected replay evaluator, not observations, and they never touch `evaluate.py`, `evaluate_suite.py` or the P arm. T1-m4 noted that `history.top.x.package` is never compared.
- Rows below that repeat these points are marked "known". Everything else is new.
- The saved mutation controls in the `evaluate.py` verdicts count a change in either direction as detection. `results/native/20261113T182820Z-cases-b/verdict.json` records `B2:mod.exists=0` as `detected: true` although the field moved from mismatch to match. `20261113T204405Z-stagec2/verdict.json` records `M5:d.exists=0` the same way. These two controls certified exactly the acceptances E-c1 and E-c2 below.

## Accepted wrong observations and the smallest repair

Proposals only. None is applied.

1. E-b1, E-c1, E-c2 (`evaluate.py`, contract-matching wrong observations). In `evaluate_case`, when any field with `predicted_as_built` fails its prediction, mark the case so a contract match cannot read as plain CONFORMS. For example, append ` as_built_refuted=<fields>` to the `per_case` line and count the case under a separate key such as `CONFORMS-AGAINST-AS-BUILT`. Make `--mutate` controls direction-aware: report `detected` only when the mutated field's match becomes `False`.
2. E-b2 (`evaluate.py`, row attributed to the wrong module). Add `"<slot>.hist.row1.Package": {"expect": "<module>"}` to the 29 case/row pairs whose driver observes it (A0, A4 and A5 first), then re-evaluate with `--use-current`.
3. E-c3 (`evaluate.py`, deviation reported as INCOMPLETE). Guard fields that exist only for a present module or row with the existing `when` form, for example `par.dev` with `when: {"field": "par.exists", "expect": "1"}` and `dep.hist.row1.*` with `when: {"field": "dep.hist.rows", "expect": "1"}`.
4. E-d (`evaluate.py`, open transaction). Add `"load.tlevel": {"expect": "0"}` (`update.tlevel` for S3*) to the 23 cases that observe it without a claim. The evaluator-only alternative is to fail any unlisted observed `(load|update).tlevel` other than `0`.
5. E-d2 (`evaluate.py`, conflicting duplicate). Use the `dup` list it already builds: a case with a conflicting repeated field becomes INCOMPLETE, as `evaluate_replay2.py` does.
6. R-d (`evaluate_replay.py` and `evaluate_replay2.py`, precondition). In `evaluate()`, compare `before.modules.<slot>.manifest_present` (and `version` when present) with `inputs.installed_before` for `top` and `inputs.dependencies[i].installed_before`. Treat a mismatch like a failed setup marker (`setup_bad`), which makes the case INCOMPLETE.
7. S-d, S-d2 (`evaluate_suite.py`). Require IPM's `Methods:` line for PASS (`elif not ipm: verdict = "INCOMPLETE"`). Require its total to equal `len(methods)`, because IPM counts skipped methods as passed and the extractor lists them with status 2.
8. P-a2 (`explore.py`, nc-gap class probes). Normalize `compiled/V:x` to `compiled` and add the N2* markers to `CLASS_OF`/`observe()`, or at least fail when an observed class is `absent` while the model installs its module.
9. P-d1 (`explore.py`, transaction level). Emit `o["tlevel"] = str(env.tl)` in `observe()` and add `tlevel` to the compared key set.
10. P-d2 (`explore.py`, phases). Keep the last phase's open or closed state in the compared row and derive the model's value from `ended` and the crash point.
11. P-c3, P-e (observations with no checker). Record which findings cite each not-expressed or unread observation. `inst-dep-conformance-coverage` (and an equivalent for `r4-*`) should fail when that observation is a finding's only evidence.

## Limits

- The plausibility of each wrong observation is a judgment. E-b2 needs a driver fault, because the driver selects rows by `Package`. S-d needs a rerun of the same suite in the same namespace. R-d needs a leftover module, which the `-b` reruns with fresh prefixes were designed to avoid.
- `evaluate.py` is a contract checker. Its acceptance of E-b1 and E-c1 is how it was designed. The finding is that nothing in its reported verdict distinguishes these from real conformance.
- Only the `evaluate_replay.py` cases above were edited. The other 39 return-b cases, and the terminate and SIGKILL runs, were not calibrated.
